Kosmos Browser: feature inventory

Edited 2026-10-27docs/browser-features.md

Status: specification, not code. Branch task/templeos-shell. Companion documents: browser-architecture.md (how these features are built) and browser-test-sites.md (what to test them on). Written 2026-10-27.

How to read this#

  • Priority. P0 = needed for a usable browser (we do not ship without it). P1 = expected by a Chrome user within the first month of use. P2 = real Chrome feature, later or never.
  • Effort. S = under a week of one agent. M = one to three weeks. L = more than three weeks, or depends on another L item.
  • Provider. Where the feature actually runs: guest (HolyC, TempleOS side), host-engine (headless Chrome, driven by CDP), host-store (our SQLite profile store, browser-architecture.md section a), host-shell (our Python bridge, no Chrome involved), or none (out of scope). CDP domain names are given where the feature has one.
  • Sources. Each group ends with the URLs used. Anything not backed by a source below is marked (memory) and should be checked before a gate depends on it.

Verified facts that shape the inventory#

These are the facts this document depends on. Each was checked in this pass.

  1. Local Chrome is 156.0.8078.48 (/Applications/Google Chrome.app, --version, checked on this Mac).
  2. Chrome 136+ ignores --remote-debugging-port and --remote-debugging-pipe when the data directory is the default one. Any automation needs a non-default --user-data-dir. Source: Chromium issue 417456892 and secondary write-ups (for example the Chrome 136/144 requirements PR). The tracker text is the primary source; the rest are secondary.
  3. Chrome 137+ branded builds no longer load extensions from --load-extension. Chromium and Chrome for Testing still do. Source: Chromium extensions group PSA, Chrome Extensions news, June 2025. Consequence: our extension host must run extensions itself (architecture section g). Nothing in the extension plan depends on the flag.
  4. Chrome 144+ prompts the user to allow each attach to a running browser. Secondary sources only (chrome-devtools-mcp issue 1794, issue 825). This does not affect us if we launch our own throwaway instance with the debug flags; it would matter if we ever attached to the user's real Chrome, which we will not do.
  5. The old headless mode left the main binary in Chrome 132. The default --headless now runs the full Chrome; the old-style shell is a separate chrome-headless-shell binary. Sources: Chrome headless docs, headless shell post, Chrome for Testing.
  6. Chrome's MV3 extension namespaces (the full list, as published): accessibilityFeatures, action, alarms, audio, bookmarks, browsingData, certificateProvider, commands, contentSettings, contextMenus, cookies, debugger, declarativeContent, declarativeNetRequest, desktopCapture, devtools. (inspectedWindow, network, panels, performance, recorder), dns, documentScan, dom, downloads, enterprise., events, extension, fileSystemProvider, fontSettings, gcm, history, i18n, identity, idle, input.ime, instanceID, management, notifications, offscreen, omnibox, pageCapture, permissions, platformKeys, power, printerProvider, printing, privacy, processes, proxy, readingList, runtime, scripting, search, sessions, sidePanel, storage, system.*, tabCapture, tabGroups, tabs, topSites, tts, userScripts, webAuthenticationProxy, webNavigation, webRequest, windows. Source: chrome.* reference.
  7. Install-time permission warnings: permissions with a warning show a dialog at install, and adding one to an installed extension disables it until accepted. activeTab shows none. Some warnings are suppressed when paired (for example tabs with <all_urls>). Source: permission warnings.
  8. DevTools panels (official list): Elements, Styles, Console, Sources, Network, Performance, Recorder, Rendering, Security, Memory, Lighthouse, Application, Animations, Changes, Coverage, CSS overview, Issues, Layers, Media, Memory Inspector, Network conditions, Performance monitor, Protocol monitor, Quick source, Sensors, WebAudio, WebAuthn, Autofill. Source: DevTools overview. Accessibility is a sidebar tool, not a panel. Source: same page.
  9. Widevine is closed-source and not redistributable in open builds. Chromium builds ship without it. Sources: Chromium Widevine DRM notes, chromium-dev thread. This is a secondary reading of licensing, not a Google licence document.
  10. Not verified in this pass: the exact CDP method list. The CDP index page could not be fetched at its tot path (404), and the DOMSnapshot page returned only a redirect. CDP domain and method names in this document are from memory and are marked as such where they matter; browser-architecture.md lists the ones the design needs so the M1 spike can confirm them against the protocol JSON that ships with Chrome 156.

1. Tabs and windows#

Feature P Effort Provider Notes
Tab strip with rounded tabs, close button, new tab button P0 M guest Tab state lives in the guest; each tab maps to one host browser context and one page target.
Several tabs, switching, close, reopen closed (Ctrl+Shift+T) P0 / P1 S guest + host-store Closed-tab stack is in the store so it survives a restart. Switching does not reload the page; the host keeps the page alive.
Tab title and favicon P0 / P1 S host-engine (Target, Page), guest Title from the page target; favicon fetched by the host and sent as a small image.
Loading indicator per tab, stop button P0 S host-engine (Page lifecycle events)
Tab crash / hang page ("Aw, snap" style) P0 S host-engine (Target.targetCrashed) Show our own error page; never show the Chrome error page.
Pinned tabs P1 S guest + host-store Pinned tabs keep their order and show only the icon.
Tab groups (name, colour, collapse) P2 M guest + host-store Chrome has tabGroups in MV3; for us it is UI only.
Drag tabs to reorder; drag out to a new window P1 / P2 M guest Dragging out to a second window needs a second window. Multi-window is P2 because the desktop has one framebuffer.
Windows (one window per browser window, or single-window with tabs) P1 M guest Start with one window; a second window opens as another app window in the desktop.
Session restore after restart P1 M host-store Tab URLs, titles, scroll position (scroll offset, not page state).
Discard (unload background tabs) P2 M host-engine (Page.navigate to about:blank, or Target.closeTarget + reopen) Chrome discards under memory pressure. We keep a stored URL and reload on activate.
Sleep / memory saver P2 S host-shell Same as discard.
Incognito window P1 S host-engine (Target.createBrowserContext) Separate browser context, no store writes, cookies discarded on close. Chrome's incognito has more features (it hides extensions by default).
Guest keyboard shortcuts for tab operations (Ctrl+T, Ctrl+W, Ctrl+Tab) P0 S guest TempleOS key codes differ from macOS ones; map on the guest and document the mapping.

Sources: Chrome tab features (memory for the exact URL), tabGroups API, sessions API, Target domain (memory for the exact URL: the tot path returns 404 from this environment).

2. Omnibox (address bar and search)#

Feature P Effort Provider Notes
Type URL, Enter loads it P0 S guest Already in v0.
Scheme inference (http:// for hosts, https:// by default) P0 S host-shell Keep the v0 rule, moved to the host so the guest does no URL work beyond sending text.
Search when the text is not a URL, with a configurable engine P0 S host-shell Default: a search URL template in settings. The v0 used DuckDuckGo's HTML endpoint; keep a fixed template and allow a change in settings.
Suggestions from history and bookmarks (as you type) P1 M host-store Prefix and fuzzy match over our store. Not from a search provider in v1 (that is a network request the user did not ask for).
Search-provider suggestions (the search engine's autocomplete) P2 M host-shell, with approval Off by default; needs a settings toggle and a prompt the first time.
Omnibox keywords and shortcuts (type @ for a site search) P2 M host-shell Chrome's omnibox MV3 API covers extension keywords.
Security indicator (https, insecure, certificate error) P0 S host-engine (Security domain, Page.getNavigationHistory) Padlock glyph in the omnibox. Certificate errors open a host-generated interstitial that the guest can only approve with an explicit prompt.
Copy URL, edit, select all, paste with Ctrl+V P0 S guest Clipboard between the guest and the host is out of v1 unless the Aiwnios build can reach the Mac clipboard (see architecture risks).
Show full URL on focus P1 S guest

Sources: Chrome omnibox help (memory for the exact URL), omnibox API, Security domain (memory).

3. Navigation#

Feature P Effort Provider Notes
Back, forward, reload, stop P0 S host-engine (Page.navigateToHistoryEntry, Page.reload, Page.stopLoading) Reload also re-sends the page display list.
Hold back or forward for the history menu P1 S host-engine (Page.getNavigationHistory)
Link clicks and same-page anchors P0 M host-engine (Input dispatch; the page navigates) Clicking a link goes to the host as a mouse event, not as a guest-side navigation. The host decides what happened (new tab, new window, download, form).
Middle-click, Ctrl-click, Shift-click, target=_blank P1 M host-engine (Target.createTarget, Page.frameNavigated) The guest maps modifiers to a "new tab" request.
Redirects and the final URL in the omnibox P0 S host-engine (Page.frameNavigated)
Client-side navigation (History API, hash changes) P0 M host-engine (Page.navigatedWithinDocument) SPA route changes must update the omnibox without a reload.
Open in a new tab from the link context menu P1 S guest + host-engine
Page not found, DNS failure, offline pages P0 S host-engine (Network.loadingFailed), host-shell Chrome's error page is replaced by ours; the reason text comes from the host.
Navigation prompts: "leave site" on a form with edits P2 M host-engine (Page.javascriptDialogOpening, beforeunload)
Form submission (POST) P0 M host-engine Outward action: the guest shows "Send form data to ?" before submission. GET forms are navigations and need no prompt.

Sources: Page domain (memory for the exact URL), Network.loadingFailed (memory).

6. Downloads#

Feature P Effort Provider Notes
Download on link or Content-Disposition, with a prompt P0 M host-engine (Browser.setDownloadBehavior, Browser.downloadWillBegin, Browser.downloadProgress) Outward action: prompt "Download () from ?" before any byte is written. Default behaviour is deny.
Download bar and download list P1 M guest + host-store Shows progress, pause (P2), open, show.
Save into the guest disk (B:) P1 S host-shell + guest file service The guest saves on the TempleOS disk after the user confirms.
Save to the host Mac Downloads folder P2 S host-shell, with approval Only after the user picks it; a host file-write permission prompt.
Dangerous file types (.exe, .dmg, .app, .sh, .command, .pkg, scripts) P0 S host-shell Refuse by default; allow only after a second prompt. Do not run downloaded files anywhere.
Resume interrupted downloads P2 M host-shell
Downloads on the host using Chrome's own downloader P0 included above host-engine Chrome does the HTTP; we move the bytes. Keep Chrome's download store out of the real profile (it is throwaway).

Sources: Browser domain (memory for the exact URL), downloads API.

7. Find in page, zoom, print and PDF#

Feature P Effort Provider Notes
Find in page (Ctrl+F) with match count and next or previous P0 M host-engine (Runtime, a find routine in page context; or the DOMSnapshot text boxes) Chrome's find-in-page is a native browser feature with no full CDP call (memory). We search the text boxes in the display list on the host and return hit rectangles. Search runs on the host; the guest draws the highlights.
Find highlights (all matches, active match) P0 S guest
Zoom in, out, reset (Ctrl +/-/0) P0 S host-engine (Emulation.setPageScaleFactor or the device scale) Zoom changes layout, so the host re-lays out; the guest only scales. Pinch zoom is P2.
Per-site zoom P2 S host-store
Print (Ctrl+P) to PDF P1 M host-engine (Page.printToPDF) Output goes to the host file store after a prompt. The guest cannot show a PDF viewer yet.
Print to printer P2 M host-shell Host printer dialog; a prompt.
Save page as (HTML, MHTML) P2 S host-engine (Page.captureSnapshot for MHTML)

Sources: Page.printToPDF (memory), Emulation domain (memory).

8. Passwords, autofill and payments#

Feature P Effort Provider Notes
Password manager Out of scope none none Security reasons. The guest never sees a password, and the host does no credential autofill.
Keychain access on the Mac Out of scope unless approved none host-shell Only after an explicit user approval per use. Default launch uses a mock keychain.
Autofill of addresses and card numbers Out of scope none none Payment and identity data stay out of the guest.
Autocomplete of plain form text from history (the browser's own form-history) P2 M host-store Form-history is the lowest-risk item here. Off by default.
Chrome's own password store in the throwaway profile Disable S host-engine (launch flags and prefs) Set the password-manager and autofill prefs off in the throwaway profile's Preferences file before launch. Verify the flag names on Chrome 156 (memory).

Sources: DevTools overview (lists "Autofill" as a panel; we do not need it).

9. Permissions and site settings#

Feature P Effort Provider Notes
Permission prompts (camera, microphone, location, notifications, clipboard, MIDI, USB, Bluetooth) P0 M host-engine (Browser.setPermission) Outward action / sensitive: every request is shown in the guest and is answered by the user. Default: deny. No device access exists in the guest; a camera prompt answers "no" in v1.
Site settings page (per-origin permission, cookies, JavaScript on or off) P1 M guest + host-store
JavaScript on/off per site P1 S host-engine (Emulation.setScriptExecutionDisabled) Chrome's content setting; useful for debugging and for battery.
Popups and redirects P0 S host-engine (Target handling) Block by default with an indicator in the omnibox.
Pop-up exceptions P2 S host-store
Notifications Out of scope none none The guest has no notification service.
Clipboard read P2 S host-engine Prompt before the page reads the clipboard.
Geolocation P2 S host-engine (Emulation.setGeolocationOverride) Prompt; the host Mac's location is not sent unless approved.

Sources: permissions API, Chrome site settings help (memory for the exact URL).

10. Cookies and storage#

Feature P Effort Provider Notes
Cookies held by the host browser context, per tab context P0 S host-engine (browser context, Storage.*) The guest never receives cookies, tokens or Set-Cookie. The page only sees its own cookies, through the page.
Third-party cookie blocking P1 S host-engine (launch flag or prefs) Chrome's default is now partially blocked (memory; verify on 156). We keep the Chrome default and expose a toggle.
Cookie viewer (name, domain, expiry, delete) P1 M guest, host-engine (Storage.getCookies, Storage.deleteCookies) This is also a DevTools Application panel item.
localStorage, sessionStorage, IndexedDB, Cache Storage viewer P1 M host-engine (Storage, DOMStorage, IndexedDB domains) DevTools Application.
Service workers P2 M host-engine (ServiceWorker domain) Chrome runs them for us; the viewer is P2.
Clear site data P1 S host-engine (Storage.clearDataForOrigin)

Sources: cookies API, storage API.

11. Extensions#

11a. Extension host (our own)#

Chrome 137+ branded builds do not load extensions from the command line (verified fact 3), so we run them ourselves. The minimal and honest plan is in browser-architecture.md section g. The feature list here is the MV3 subset.

Feature P Effort Provider Notes
Load an unpacked extension folder (user chooses it) P1 M host-shell Prompt for permissions.
Install from a .crx or the Chrome Web Store Out of scope for v1 none none Store downloads are an untrusted source; CRX install is a prompt-and-review flow we do not build in v1. Store terms also apply (memory).
manifest.json: name, version, description, icons, permissions, host_permissions P1 S host-shell
content_scripts (matches, run_at, js, css) P1 M host-engine (Page.addScriptToEvaluateOnNewDocument, Page.createIsolatedWorld) Isolated world per extension.
action (toolbar button and popup) P1 M host-engine (a page target for the popup), guest (button and popup area) The popup renders as a host page target; the guest paints its display list in a popup area.
background service worker P1 L host-engine (a dedicated page target with our shim) MV3 service workers have no DOM; ours run in a page target. Behaviour differs.
chrome.runtime (sendMessage, onMessage, getURL, getManifest, id) P1 M host-shell (shim)
chrome.storage (local; sync is local-only for us) P1 S host-store
chrome.tabs (query, create, update, remove, sendMessage) P1 M host-shell + host-engine tabs permission warning.
chrome.scripting (executeScript, insertCSS, registerContentScripts) P1 M host-engine (Runtime.evaluate in an isolated world)
chrome.alarms P1 S host-shell
chrome.i18n P1 S host-shell
chrome.permissions (request, contains, remove) P1 S host-shell Prompts in the guest.
chrome.action (setBadgeText, setIcon, setPopup) P1 S host-shell
chrome.contextMenus P2 M guest
chrome.commands (keyboard shortcuts) P2 S guest
chrome.webNavigation P2 S host-engine (Page events)
chrome.cookies P2 M host-engine (Storage) cookies permission, prompt.
chrome.bookmarks, chrome.history, chrome.downloads P2 M host-store Permission prompts.
chrome.declarativeNetRequest P2 L host-engine (Fetch domain) Ad blockers need this; large effort, honest limit.
chrome.webRequest (blocking) Out of scope none none MV2-era; not in MV3 for most uses.
chrome.debugger Out of scope none none An extension that drives other tabs through CDP is a security boundary we do not expose.
chrome.sidePanel, chrome.offscreen, chrome.tabGroups P2 M guest
chrome.identity, chrome.management, chrome.enterprise.* Out of scope none none OAuth and enterprise policy.
chrome.nativeMessaging Out of scope none none Would let an extension run host programs.

Sources: chrome.* reference, permission warnings, MV3 overview (memory for the exact URL).

12. DevTools#

DevTools is a host-side product: the page is the host Chrome; the panels are our own guest UI that talks to CDP domains. The mapping is in browser-architecture.md section f. Per panel:

Panel P Effort CDP domains Notes
Elements (DOM tree, outer HTML, select to highlight) P1 M DOM, DOMSnapshot, Overlay Tree from DOM.getDocument; highlight on the page via Overlay.highlightNode, and as a guest-side box.
Elements: Styles pane (computed and matched rules) P2 L CSS (getMatchedStylesForNode, getComputedStyleForNode) Edit styles in place is P2.
Elements: box model P2 M DOM.getBoxModel
Console (messages, eval, errors, warnings) P1 M Runtime (consoleAPICalled, exceptionThrown), Log, Console Our console input is a guest text field that calls Runtime.evaluate.
Sources (files, breakpoints, step) P2 L Debugger, Runtime Breakpoints and stepping go through the host. Large; the guest shows source text and line numbers.
Network (request list, timing, headers, response size) P1 M Network (requestWillBeSent, responseReceived, loadingFinished) Headers are shown to the user; they are not a secret store. Redact cookies and Authorization by default.
Application (cookies, storage, service workers, cache) P1 M Storage, DOMStorage, IndexedDB, CacheStorage, ServiceWorker Storage viewer shares its code with section 10.
Performance (basic recording, a timeline of the main thread) P2 L Tracing, Profiler, Performance Basic only: start, stop, a flame summary. The Chrome Performance panel is much more (see the official page).
Memory (heap snapshot) P2 L HeapProfiler Heap snapshots are large; cap the size.
Lighthouse P2 L none (runs Lighthouse on the host) Needs Node and the Lighthouse package on the host; out of the first version.
Security (certificate and mixed content summary) P2 S Security
Issues, Rendering, Layers, Animations Out of scope none none
Recorder Out of scope none none
Autofill panel Out of scope none none Section 8.
Accessibility tree P2 M Accessibility (getFullAXTree) Reuse for section 14.

Sources: DevTools overview, Performance panel overview. The Elements, Network, Sources, Application, Memory and Lighthouse descriptions came from secondary guides, not official pages, and should be checked before M5.

15. Media#

Feature P Effort Provider Notes
Images (JPEG, PNG, GIF first frame, WebP, AVIF, SVG) P0 M host-engine (decode by Chrome), guest (cache and paint) Downscaled on the host to exact paint size (architecture section d). Animated GIF: first frame in v1.
Video (HTML5 video element) P1 L host-engine (screenshot tiles at intervals), host-shell (poster), guest (controls) The guest cannot decode video. Plan: poster frame plus a tile stream at 2 to 5 frames a second for a short clip; long video is out of scope in v1.
Audio (HTML5 audio) P2 L none in guest; host plays on the Mac speakers only with user approval The TempleOS guest has no audio driver (native-apps plan). Audio plays on the host only after the user's explicit approval per page, with a mute control.
Widevine and other DRM (EME) Out of scope none none Verified fact 9. DRM content shows a placeholder: "Protected content is not supported".
WebGL and canvas P1 L host-engine (screenshot tiles of the element) Read-back of canvas pixels is slow; the tile stream is the fallback. Interactivity works through input events (the page keeps running on the host).
Media controls and play/pause state P2 M host-engine (Runtime on the media element)
Picture-in-picture Out of scope none none

Sources: Chrome media support (memory), Widevine notes.

Suggested priority cut#

P0 for the first usable build (M3): tab strip, omnibox with search, navigation, display list rendering, link clicks, text input into forms, scroll, zoom, find, downloads with prompt, permission prompts (deny), new-tab page, about page, keyboard shortcuts, main menu, security indicator.

P1 (M4 and M5): bookmarks and bar, history, session restore, reader mode, cookies viewer, site settings, print to PDF, DevTools Elements, Console, Network, Application; extensions: manifest, content scripts, action, background, storage, runtime, tabs, scripting, alarms.

P2 and out of scope: everything marked as such above. Sources of pressure: DevTools Performance and Memory, declarativeNetRequest, sync, passwords.

Open questions for the user#

  1. Is the "Chrome Web Store installs" item out of scope for v1 (proposed: yes)?
  2. Is downloading to the host's Downloads folder acceptable as P2 with a prompt (proposed: yes)?
  3. Should audio play on the host Mac when a user approves it (proposed: yes, P2 with a mute control)?
  4. The name in the UI: "Kosmos Browser" with a Chrome-like layout (proposed) rather than any Google mark.
