Electron apps in the HolyC desktop (prototype)

Edited 2026-10-27docs/electron-apps.md

Date 2026-10-27. Code: apps-host/ (host), desk3/03d-electronapp.HC (guest, off by default). Context: electron-tauri-support-research.md (why not pixel capture of the Mac screen), browser-architecture.md (CDP over a pipe, display-list bands), apps/applications-folder.md (manifest, permissions). Measured on this Mac with a VS Code OSS build (Caret 1.116, Electron 39.8.5, Chromium 142) that was already on disk.

Architecture#

An Electron app is a Chromium renderer plus a Node main process. appd launches the app with --remote-debugging-pipe (fds 3 and 4, no port), so the desktop drives the renderer exactly like the browser engine: CDP Page, DOMSnapshot, Input, Emulation, Runtime. Electron 39 accepts the Chromium switch; only Browser.getWindowForTarget is missing (no window bounds), everything else probed ok.

Two content routes, one control path: 1. Display list: attach.display_list = DOMSnapshot -> browser/host/dlist.py bands (reused, unmodified). Fits plain DOM; used for the report. 2. Pixel tiles (labelled fallback, the one wired to the guest): the page is laid out at the exact surface size (Emulation.setDeviceMetricsOverride, DSF 1), screenshotted, diffed in 16-row strips, sent as RGB565 or 16-colour RLE rects. Input: guest mouse/wheel/key -> Input.dispatchMouseEvent/KeyEvent; surface px = CSS px, so no mapping error. Focus rule: the front guest window sends focus on/off -> Emulation.setFocusEmulationEnabled (the app only types while the guest window is front; it never raises the Mac window).

Install flow (install.py)#

Extraction rejects absolute paths, .., backslashes, symlinks leaving the tree, writes through symlinks, hard links, devices, duplicates, size bombs. Tested only against local archives (zip of the on-disk VS Code, 296 MB, served by python3 -m http.server on 127.0.0.1). Nothing was downloaded. The VS Code build is ad hoc signed and does not verify (code has no resources), so it needs --allow-adhoc. Fuses of this build: RunAsNode on, EnableNodeCliInspectArguments on, cookie encryption off, ASAR integrity off (so patching and CDP are not blocked).

Measured (loopback, no QEMU UART in the path)#

Display list of VS Code, 1440x900 103 items, 3.9 KB, capture 10 ms + encode 7 ms; tile similarity 0.874 vs screenshot (mostly flat dark area, so flattering)
Screenshot of the page 73 ms round trip (2880x1800 PNG 110 KB); at DSF 1, 36 ms p50
Tile stream, 1000x640 first frame 63 to 216 KB; capture 36 ms, encode 4 ms, send 2 ms (p50)

What the display-list route cannot do#

Canvas and WebGL, the Monaco editor's glyph layers when it renders to canvas, <webview>/iframe content from other processes, native menus and title bar, OS dialogs, <select> popups, video, codicon/icon fonts (private-use glyphs, shown as boxes), SVG (grey placeholder), text shaping. Proposal: DOM-heavy shells (sidebar, tabs, settings) as display list; editor, terminal, webviews, canvas as pixel tiles, per target rectangle. The tile route covers everything a page paints but not what the OS paints around it.

Security and permissions#

Manifest permissions: storage:own, host:files:ro|rw (one workspace folder), host:net, host:downloads, shell:clipboard|notify|agent. First launch: the bridge sends a question (what the app asks, workspace path, "not signed") to the guest sheet; Allow records approvals.json on the host. More permissions in an update invalidate it. Revoke with appd revoke. Kill switch: appd stop (Browser.close), appd kill (supervisor, else the verified process tree only; tested: 8 processes to 0). Closing the last window stops the app. Enforced by the host: profile, extensions, downloads under profiles/<id>/; minimal environment (no tokens, throwaway HOME and TMPDIR); --use-mock-keychain (without it Electron blocked on a Keychain prompt); workspace must be a real folder, not /, $HOME, ~/.ssh, Library, ...; network off by Chromium flags unless host:net (renderers only; the Node main process is not covered); eval only with shell:agent. Not enforced: an unsandboxed app can read anything the user can (tested: Electron as node read a decoy outside its workspace). sandbox-exec (deprecated, present): a profile denying $HOME reads and network confines the Electron runtime in node mode (workspace file read, outside read EPERM, write outside EPERM, net EPERM; tests/test_perms.py). The full Chromium app fails under it ("sandbox initialization failed"): Chromium cannot nest its own seatbelt, and --no-sandbox would trade renderer isolation for it. App Sandbox needs a signed bundle with entitlements: not tried. A real boundary needs a container or VM (see os-foundation-plan.md). Electron wants short profile paths (103-byte socket limit): appd aliases through /tmp/ksa-<uid>/.

Tauri and WebKit apps#

No CDP on macOS WKWebView (Safari inspector only, private API; tauri-driver has no macOS driver). Options: pixel capture of the window (ScreenCaptureKit) as in the research doc, or run the frontend as a page in headless Chromium with the Rust side mocked (per app, needs source).
