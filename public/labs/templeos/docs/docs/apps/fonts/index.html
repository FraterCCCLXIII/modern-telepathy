Font Manager: plan

Edited 2026-10-27docs/apps/fonts.md

Status: plan, not code. Branch task/templeos-shell. Written 2026-10-27. Read with docs/browser-architecture.md section h5a (the font stages A to D) and h6 (non-Latin runs), docs/apps/music.md (channel families), and docs/apps/00-kosmos-os-primitives.md (no os.fonts@1 contract exists yet).

Tags: [V] checked in a repo or on this Mac, file named. [R] from a web search this session (snippets, URL given). [M] from memory, to verify.

1. Purpose#

A desk app that lists the fonts the user chooses, previews any text in any of them at any size, and activates a font for the desk's own apps (Notes, the browser, slides). The guest never parses a font file. The host scans, validates and rasterises. The guest receives bitmaps, metrics and coverage tables.

"Activate" means: the desk's font table gains a family the apps can request by name. It does not install a font into macOS.

2. Features#

Reference set: Font Book, FontBase, Typeface.

Priority Feature Reference
P0 List families and styles from chosen folders and the system font folders (read-only) FontBase keeps files where they are and shows them without a system install [R] (fontba.se/learn/font-activation)
P0 Activate and deactivate per font; active set survives restart FontBase: new fonts start inactive, active ones return at launch [R] (fontba.se/learn/font-activation)
P0 Preview: editable sample text, size slider, weight picker Typeface preview settings [R] (thesweetbits.com/tools/typeface/)
P0 Metadata: name, version, licence name, weight, glyph count Font Book info panel (not fetched)
P1 Charset grid: glyphs by Unicode block, with coverage Typeface organisation [R]
P1 Collections, tags, search FontBase free tier includes collections and watched folders [R] (fontba.se/learn/font-activation)
P1 Variable fonts: axis sliders, named instances Typeface (variable fonts not checked) [M]
P1 Compare two fonts side by side Typeface Compare [R] (thesweetbits.com/tools/typeface/)
P2 OpenType features (stylistic sets, figures) FontBase shows features, free tier [R]
P2 Google Fonts catalogue, downloads from the host FontBase and Typeface both integrate Google Fonts [R]; a download is a PROMPT (section 9)
Out Cloud sync, auto-activate for other apps Typeface's auto-activation and paid tiers [R]: not in scope

Typeface is Mac-only and paid [R]. FontBase is cross-platform with a paid tier [R]. Font Book is free and built in, and reviewers call it basic [R] (thesweetbits.com), but we did not open Apple's guide. Pricing and tiers change, so none of them is a dependency.

3. Architecture#

Rules:

  1. Parsing happens on the host only, in a worker process with CPU time, memory and file-size limits. The guest never receives a font file for a user or system font.
  2. Rendering is the host's job. The host draws text in a font at a size and weight, and sends a bitmap atlas or a run image.
  3. Only validated results reach the guest. A failed font shows a reason ("table glyf truncated") and is never rendered.

3.1 Host tools#

Installed [V]: Python 3.13, fontTools (MIT [R], pypi.org/project/fonttools), Pillow (its ImageFont uses FreeType [M]). Not installed [V]: the Python freetype binding. Not checked: CoreText via PyObjC, HarfBuzz. CoreText covers macOS runs, so HarfBuzz is needed only for our own rasteriser, which we do not plan to build.

4. Three ways to get glyphs to the guest#

Option How Cost Verdict
A. Build-time atlases (the current pipeline) scripts/gen-font.py rasterises Inter into assets/KSFONT.BIN at 4 sizes and 2 scales, ASCII only [V] zero at run time; fixed set; baked into the boot image keep for built-in faces
B. Host atlases per request the host rasterises a family at a size, weight and range, sends it over the channel, and the guest caches it by hash link time per new size; needs a cache use for user and system fonts
C. Port stb_truetype to HolyC and ship TTF bytes the guest parses fonts and draws any size a port of about 5,000 lines of C (brief figure, [M]; check the header); font bytes in guest RAM; untrusted parsing in the guest breaks rule 1; no shaping defer, only for trusted built-in OFL fonts at M6 (browser h5a stage D)

stb_truetype is a single-file library, public domain or MIT, dual licensed per file [R] (github.com/nothings/stb). That makes option C legally clean; the problem is safety and size, not licence.

4.1 Atlas format#

Current format [V: scripts/gen-font.py docstring]: per face, one byte ascent, one byte line height, then 95 records of U16 advance (1/16 px), U8 w, U8 h, I8 bearing x, I8 bearing y, U16 offset, then U32 data length and 4-bit alpha pixels.

The U16 offset is a limit. Measured on this machine with the current script [V: run in a scratch folder]: the eight ASCII faces hold 3.0, 3.4, 2.3, 8.6, 10.5, 11.8, 7.7 and 32.2 KB of pixel data. The largest face is 32,237 bytes, half the 65,535-byte offset range. Browser stage B (about 350 glyphs, roughly 3.7 times the ASCII set [browser-architecture h5a]) would take the 44 px face to about 120 KB [estimate], and the offsets would wrap silently.

Format v2 (proposal): U32 offsets, one page per 64 KB, and a family header with the Unicode ranges present. Every guest atlas carries its own version byte, so the v1 faces keep working during migration.

4.2 Atlas cache#

Key: SHA-256 over (font file hash, face index, variation axes, size, weight, scale, code range, renderer version). Host cache under the user's cache folder. Guest RAM cache with a budget (browser budget reused, section d3 in browser-architecture). The guest sends HAVE with the hashes it holds, so a reconnect costs nothing.

Cost check with the measured numbers: an ASCII atlas for one family at four sizes is about 20 to 60 KB [estimate, from the table above]. At the reported 47 KB/s serial rate that is about 1 s. At the old 1.4 to 2.7 KB/s lockstep rate it is 10 to 40 s. So the channel spike gate (50 KB/s) decides whether option B is interactive. Without the gate it is a background fetch with a placeholder face.

5. Non-Latin text and emoji#

  • Latin, Greek, Cyrillic (stage B): atlases in format v2 from Inter, which covers them [V: browser h5a; coverage to confirm in the font file].
  • Everything else (CJK, Arabic, Hebrew, Devanagari, Thai, any font the user adds): a run image (RUNIMG, browser 0x09 and h6). The host shapes and draws the run in the font with CoreText, sends an alpha mask and the colour token, and the guest caches it by hash. Cost estimate from h6: a 20-character CJK run is about 8 KB compressed.
  • Emoji: Apple Color Emoji ships with macOS and its font terms restrict redistribution [M]. We render emoji on the host only and send RUNIMG RGBA. We never bundle it. Noto Color Emoji is an open alternative, licence to be checked [M].
  • Encoding: the guest is 8-bit HolyC text. The font manager shows UTF-8 names by sending them as a pre-rendered label or a transliterated ASCII name. Typed input in the preview field is ASCII in v1.

6. Variable fonts#

The host reads the fvar table and its named instances. For a requested axis set (for example wght 620 and wdth 100), it makes a static instance with fontTools' instancer [M: fontTools.varLib.instancer], then rasterises that. The guest sees each instance as an ordinary face, with a name like "Family Bold 620". Slider changes are debounced to 150 ms so the link is not flooded while dragging.

7. System fonts and redistribution#

  • macOS system fonts (in /System/Library/Fonts and /Library/Fonts) are listed and previewed on the host only. Their licence terms restrict redistribution and extraction [M, Apple's font terms not checked].
  • Rule: the host may render a system font for the local user's preview. It must not write those glyphs into the repo, the boot image, the test fixtures or any shared file. The boot image stamp in scripts/image-path.sh lists its inputs explicitly [V]; system-font atlases are excluded from it.
  • User-added fonts follow their own licence. The index stores the licence name from the font's name table (nameID 13 and 14) [M] and shows it.
  • ls of /System/Library/Fonts and /Library/Fonts gives about 134 entries together [V; includes folder headers, so approximate]. Design the list for hundreds of files.

8. Licence hygiene in the repo#

  • assets/ holds KSFONT.BIN, KSICONS.BIN and LUCIDE-LICENSE.txt [V]. No OFL text is in the repo. The Inter licence the atlas uses is required by OFL 1.1 to travel with the font. Add assets/licenses/OFL-Inter.txt before the next image build.
  • scripts/gen-font.py reads Inter from an absolute path outside the repo, /Users/paulbloch/Documents/github/puter-ui/src/gui/src/fonts [V]. Vendor the two files it uses, or record their checksums and source in a README, so the build does not depend on another checkout.
  • That folder holds nine Inter weights (Black, Bold, ExtraBold, ExtraLight, Light, Medium, Regular, SemiBold, Thin) [V]. The generator uses two. Record which weights are intended.
  • OFL reserved font names: Inter's name is not reserved in what we checked [M]; any modified Inter must be renamed if it is distributed. We do not modify it.

9. Activation, consent and the channel#

Message family 0x30 to 0x3F (proposal; the browser uses 0x01 to 0x14 and music uses 0x20 to 0x2F).

Code Name Payload
0x30 FONT_LIST (H to G) font id, family, style, weight, width, source (system, user, google), glyph count, licence name. No bytes
0x31 FONT_QUERY (G to H) view, filter, sort, offset, count
0x32 PREVIEW (G to H) font id, axes, text (ASCII, up to 256 bytes), size, scale, colour token
0x33 ATLAS (H to G) hash, font id, size, weight, scale, range, format v2 data
0x34 ACTIVATE (G to H) font id, on or off; the host stores the active set
0x35 COVERAGE (H to G) code ranges present, for the charset grid
0x36 VALIDATE (H to G) ok, or a reason string, and the table that failed
0x37 ADD_FOLDER (G to H) a path chosen in a host dialog; the guest only asks, the host shows the dialog
0x2C, 0x0D, 0x0E PROMPT and answer shared with music and the browser

Activation is local, and it changes what the desk's apps see, so it needs no PROMPT. Adding a Google Fonts download, a folder outside the user's home, or any write outside the cache is a PROMPT showing the file name, size and source, with the default "no". Install of a font into macOS is never done.

Apps consume families by name: FontFace(family, weight, size, scale) returns a face id from the active table, or falls back to the built-in Inter face and records the miss. Browser pages use the same table. Slides (DeckDoc fontFamily) and Notes do the same [V: primitives 3, DeckDoc schema].

12. Milestones and gates#

Milestone Work Gate
F0 atlas format spike format v2 writer on host, reader in HolyC; one family, four sizes guest atlas matches the host render within one level per pixel, on x86 and Aiwnios (golden method in aiwnios/README.md)
F1 host index and validation scan, SQLite index, sandbox worker 500 fonts indexed; 2,000 corrupted copies of Inter (byte flips, truncation) give no crash and no hang, each with a reason
F2 guest Font Manager list, search, preview, activate activating a font makes it selectable in Notes
F3 user fonts and variable instances ATLAS for user fonts, instancer, charset grid wght 400 and 700 instances render, with distinct atlas hashes
F4 browser stage B Latin-1, Ext-A, Greek, Cyrillic in format v2 the German and Russian article gate in browser h5a
F5 run images CoreText runs for CJK, Arabic, emoji one CJK run and one emoji run legible at 2x
F6 Google Fonts catalogue fetch on the host, OFL only, PROMPT for each download a download prompt shows name and size before any byte moves

Every phase needs the owner's go. F0 is the cheapest decision: it proves or kills option B before any UI is built.

13. Test plan#

  • Golden atlases. For each built-in face and two user fonts, the atlas hash is stored; a change needs a reason.
  • Metadata golden. The index output for a fixed folder (the Inter set and two Google fonts we vendor) as JSON, compared on each run.
  • Fuzz. Byte flips and truncations of Inter in the scratch folder (never committed), with a 10 s timeout and 256 MB memory cap per worker. Pass: no crash, no hang, a reason for each failure.
  • Licence check. A script fails the build if any bundled font lacks its OFL text in assets/licenses/.
  • Boot. KS-READY stays in the 0.5 to 0.7 s range recorded for Aiwnios [V: aiwnios/README.md] after each stage.
  • Parity. golden.py on x86 and Aiwnios for the Font Manager window, once it exists.

14. Risks#

  1. Parsing risk. FreeType and fontTools are C and Python code that parse hostile input [M]. Mitigation: worker sandbox, limits, no guest parsing, patch the library as CVEs appear.
  2. Redistribution. System fonts and Apple Color Emoji. Mitigation: host-only rendering, exclusion from the image stamp and repo (section 7).
  3. Link cost. A family at four sizes can be tens of KB. Mitigation: the F0 gate decides; placeholders while atlases stream.
  4. Offset wrap (section 4.1). Mitigation: format v2 with a version byte, tested with a 44 px stress face.
  5. Font count. Hundreds of families can overwhelm the guest's RAM. Mitigation: the active set is capped (16 faces, a number to check) and atlases are evicted by LRU.
  6. Text encoding. 8-bit guest text. Mitigation: names transliterated, non-ASCII shown as run images.
  7. Stale boot image. New font assets not in scripts/image-path.sh leave an old image in use. Mitigation: add them to the stamp in the same change.
