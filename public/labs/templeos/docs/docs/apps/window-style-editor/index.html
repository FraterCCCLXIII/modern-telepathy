Window Style Editor (app 12, "Windows")

Edited 2026-10-27docs/apps/window-style-editor.md

Native desk3 app, 860 x 600, icon Lucide app-window (L_APPWIN, scripts/gen-icons.py). Left: live preview (two sample windows, one focused, one inactive, on a wallpaper strip with a Light/Dark switch), themes, Export/Import. Right: colour picker (hue strip, saturation, lightness, the 16 style tokens, Follow) and the inspector in collapsible groups. Every control changes the real desktop at once.

Controls#

  • Chrome: kind (style, card, lights, caption, none), glass window, glass title bar, blurred or sharp wallpaper, title bar opacity.
  • Geometry: corner radius 0 to 28, title bar height 36 to 56, title side padding. Windows are fixed size: no minimum size or snap gap exist.
  • Title bar: solid or gradient (angle in 15 degree steps), colours, alignment, font, title colours, inactive fade, separator.
  • Buttons: light size, spacing, colours, glyphs (never, hover, always), hover highlight, button radius, inactive fade. Minimise (yellow light, caption button) really closes with the minimise animation; maximise only raises.
  • Body: colour, opacity (below 256 turns glass on), border colour and width, inner shadow, scroll bar style (used by the editor itself: no other app has a scroll bar yet).
  • Shadow and depth: blur, offset down (no sideways offset), strength inactive and focused, colour, focus glow, focus ring.
  • Motion: open, close, minimise preset (fade, scale, slide), duration, easing (ease out, linear, in and out), reduce motion.
  • Colour schemes: follow style, Light, Dark, Graphite, Midnight glass, Warm paper, Solarized, High contrast, Temple gold. A scheme also switches to a matching desktop style so app text stays readable on the new body colour.
  • Themes (under the preview): the five desktop styles are read-only bases; Customize copies one into an editable user theme (8 slots), Save as new, Delete, Reset to base. Controls are greyed on a base theme. Rename is not implemented.

Theme string#

ws1 nmNAME ba2 kd-1 gl-1 tg0 ... one two-letter key and a decimal value per field (ws_fk in 03e), name with underscores. -1 follows the desktop style. Export prints it on COM1 (WINSTYLE ...), writes B:/WINSTYLE.TXT and shows it; Import reads that file (or the last export), checks ws1, ignores unknown keys, clamps values, makes a new user theme. Nothing is persisted otherwise.

Architecture#

ws[WS_N] (I64, defined in 01-core.HC) holds every value; -1 means follow the style, so the defaults equal the old constants. 01-winstyle.HC: WsChrome (fill, glass, gradient, border, title, buttons), WsShadow (shadow, glow, ring), motion helpers. 03e-windowstyle.HC: editor, themes, import/export. Frame (02-ui) now only animates the rectangle and calls them. Redraw by field: motion none; shadow fields only a screen redraw; title fields a 66 px strip of each layer; the rest all layers. Constants that became fields: TBAR (now ws_tb), Rad(), shadow 34/16/16/50 and colour, card/border/separator/title/button colours, traffic light radius 7 and pitch 22, close box radius 8, open scale 0.94, time constant 90 ms, glass alpha 205, border hairline, shadow margins in DirtyWin and WinNear. Shadow tile cache NTK 4 to 8 (glow adds a tile). New hit ids ID_MIN, ID_MAX.

Verified#

Aiwnios, 2x, five styles, four windows: screenshots with the defaults were pixel identical to the code before the edits (max difference 0, measured when the tree was quiet; aiwnios/winstyle-golden.HC). Real pointer clicks and drags (aiwnios/winstyle-drive.HC) worked for Customize, kind, glyphs, gradient, colour swatches, angle slider. Shots: shots/window-style-*.png. Not verified: x86 VM run, drag frame times, all presets, import round trip, motion presets, hover, scroll wheel. Limits: chained comparisons with calls (A(1)<=x<A(2)) are wrong on Aiwnios, use &&. Blur amount is on or off (the wallpaper blur is fixed).
