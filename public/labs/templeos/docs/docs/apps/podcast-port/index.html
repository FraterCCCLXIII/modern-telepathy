Podcasts: port of the Kosmos OS podcast app (phase A: host and spec; phase B: the HolyC app)

Edited 2026-10-27docs/apps/podcast-port.md

Source read 2026-10-27: kosmos-os-frame src/apps/podcast/ (13 files, 3131 lines), shared/podcastDirectory.ts (221, the 108-show directory), shared/podcastFeeds.ts (59), the server services server/services/podcast*.ts (1713) and the 82 APPS$PODCAST_* copy keys in public/locales/en/arco.json. The user's own project, no licence file: behaviour, layout, data model and copy are translated; nothing is pasted. Host side is done (apps-host/hub/svc_podcast.py, protocol in apps-host/hub/PODCAST.md, 18 offline tests pass).

1. What the source app really has (verified by reading)#

  • Shell: app id podcast ("Podcasts"), one window; a shell-level audio engine (PodcastEngine, an <audio> element) keeps playing when the window is minimised. No agent tools, intents or contracts: it only talks to the shell through the window store and /api/podcast/*.
  • Sidebar: search box; Browse section (Main Feed, Home, Browse, Library, Downloads, Transcripts); Sources (Local library, RSS feeds, Spotify, Apple Podcasts, Audible, Connect account); Manage (Settings).
  • Home: Continue listening card (Play), Following (grid of followed shows), New in your feed (episode rows), Discover more; empty state "Your feed is empty" with Browse podcasts.
  • Browse (directory): 12 category chips plus All, grouped sections or a Results list when searching or filtering (search matches title, publisher, description), cards with cover, publisher, blurb and Follow/Following. Directory show page: hero cover, publisher, episode count, blurb, Play latest, Follow, episode list with loading, refreshing and error states (previews a show without following).
  • Show page (from Home/Library): back, hero, Play latest, All episodes. Episode page: About / Transcript tabs, Play, Transcribe, Save to Drive.
  • Library: content filter chips (All, Podcasts, Audiobooks) plus Local, downloaded episodes, continue listening, your shows, episodes, "Open in provider". Downloads: locally scanned files. Transcripts: list with word counts and engine.
  • Settings: feed manager (paste RSS URL, Add feed, list with publisher and "auto-download on", remove, sync downloads).
  • Main Feed: full-screen vertical snap slides built from continue, up to 14 new episodes, up to 4 shows, a Discover slide; arrow/PageUp/PageDown keys; blurred cover backdrop; an unwired "Save to queue" button.
  • Player bar (shared MediaPlayerBar): cover, title, show, previous, play/pause, next, progress seek with elapsed and duration, volume, Transcribe, Save to Drive. Previous/next cycle through the catalog of the same source, wrapping; end of episode plays the next.
  • Cover art: server proxies the feed image; fallback is a coloured tile from one of 12 tones (sum of char codes modulo 12).
  • NOT in the source (verified by grep): playback speed, sleep timer, chapters, a real queue, shuffle, repeat, skip 15/30 s, saved resume position (progress is in memory and resets to 0 on every play), played flags, manual download. The host service adds speed, sleep timer, resume, played, download and auto-next anyway because the brief asks for them; queue and chapters stay out (S, below).

2. Data model (types.ts and podcastStore.ts)#

  • PodcastEpisode: id, title, showTitle, host, durationLabel "m:ss", publishedAt, kind podcast|audiobook, artTone (12), source local|rss|remote, provider, streamSrc, listenUrl, coverUrl, feedUrl. Episode id for RSS = "rss-" + 16 hex of sha256(feed URL, guid). Ours: eid = 10 hex of sha1(show id, guid).
  • PodcastShow: id, title, host, episodeCount, artTone, feedUrl. Feed subscription: id, url, label, publisher, addedAt, autoDownload. Directory entry: id, category (12), label, publisher, url, description. NowPlaying: episode, progress 0..100, elapsed, duration.
  • Store: three catalogs (local, rss, remote), subscribed feeds, drive saves, transcripts, selection (nav section, show, episode, directory show), filters, playing, nowPlaying. Home = RSS episodes of subscribed feeds, newest first, search and kind filter; server keeps 20 episodes per feed, 30 min cache, downloads at most 5 new per feed.
  • Ours: the same records, flattened into the S D E PS records of PODCAST.md; the guest keeps only the current page (10 rows) and the selection; the host keeps state.json (subs, progress, files, speed, autonext).

4. Mapping to desk3 (window 820 x 560 logical, body below the title bar)#

Colours only through P(C_*) so all five window styles work; cover tones are a 12-entry table mixed 60% into C_CARD. Widgets: Button (kind 0/1), Radio (category chips), Slider (volume and speed), Toggle, Check, RRFill/RRRing, Txt/TxtC, Hit, LIcon. Missing in the framework: tab strip (draw chips with Button, a selected index), text entry (copy BrowserKey/LpKey: focus flag, caret, Backspace, Enter), progress bar (use the Music seek bar: Hit region plus ks_cx), list scrolling (wheel hook + DamageL, as MusicWheel), image blit (loop of Rect per pixel from the cover record, cached in a layer).

Sidebar 170 px (6 rows of 34), main 650 px, player bar 64 px, rows 44 px (about 8 visible). Sidebar items: Main Feed, Home, Browse, Library, Downloads, Settings (Transcripts dropped).

Copy: reuse the source strings ("Your feed is empty", "Follow podcasts from Browse to see new episodes from your shows here.", "Continue listening", "New in your feed", "Browse podcasts", "No podcasts found", "Try another category or search term.", "Loading episodes...", "No episodes found for this feed."). Icons (Lucide): present in KSICONS.BIN: layers, search, settings, check, play, pause, skip-back, skip-forward, volume-2, refresh-cw (spinner), moon (sleep), star, hard-drive (downloaded), clock, music, chevron-right, x. New, add to NAMES in scripts/gen-icons.py: headphones (app icon), house, book-open, library, download, chevron-left, plus, trash-2 (8). Optional: gauge (speed).

5. Host mapping#

Search is client side in the source; ours: directory ... QUERY on the host (108 entries) and the title filter of the page on the guest. Follow = subscribe (local) then refresh (approval naming the feed host). Episode rows come 10 at a time (episodes FID off 10, 658 bytes). Cover cover ID 48 per visible row, lazily, at most one call in flight (HostCall takes turns), cached by the guest per id. Progress bar and clock from status polled at 250 ms like Music.

6. Playback decision#

Reuse the Music service (one afplay, one spectrum, one volume). Facts tested: afplay cannot open URLs (so download first, approval each), afplay -r changes speed (measured: 3 s file, rate 2 saves 1.5 s, 0.75 adds 1 s), no pause/seek in afplay (music service uses SIGSTOP and a trimmed file, a 100 to 200 ms gap). The podcast service hands one flagged entry to the Music instance and wraps spawn/position for the rate; Music's own tracks are untouched. While a podcast plays, the Music app shows it as the current track; stop in either app stops both. S only: queue, chapters (Podcasting 2.0 JSON), transcripts, shuffle, repeat, skip 15/30 s (guest can seek pos+30).
