Maps app: plan

Edited 2026-10-27docs/apps/maps.md

Status: plan only, no code. Written 2026-10-27 on task/templeos-shell. Read with docs/holyc-native-apps-plan.md and docs/browser-architecture.md sections a to d.

Evidence tags: [verified] opened or run in this pass; [reported] from a search snippet or secondary source; [memory] unchecked; [estimate] our arithmetic, for the gates to confirm.

1. Purpose and users#

A map for the TempleOS desk that works offline once a region is loaded and draws with our own renderer. Three jobs: look at a place, find a place by name or address, and drive from A to B with a line and a turn list. Users: the desk owner, on the QEMU guest (slow, ASCII text) or Aiwnios. Offline use is the main case because the guest has no network. Not in v1: transit, live traffic, street imagery, satellite.

2. Platform facts#

  • Renderer [verified, desk3/01-core.HC]: anti-aliased rounded rectangles (RRFillN), discs, one-pixel anti-aliased lines (LineN), shadows, a clip rectangle, and blended blits. There is no general polygon fill and no stroke wider than one pixel.
  • Text [verified, Txt, TW]: four Inter bitmap faces at two scales, 95 ASCII glyphs (codes 32 to 126). No glyph for ° or accented letters, so the host folds names to ASCII and the UI writes deg.
  • Icons [verified, LIcon]: Lucide strokes from KSICONS.BIN, usable for pins.
  • App model [verified, 02-ui.HC, 03-apps.HC]: apps draw in logical units, register hit regions, and use AID. The Browser (03b-browser.HC) already follows it. There is no Contacts app and no map app yet.
  • Channel [reported, browser doc b4]: about 47 KB/s on QEMU serial, to re-measure at M2; Aiwnios sockets are effectively unlimited. First paint is capped at 120 KB.
  • Host [verified locally]: Python 3 with PIL, rsvg-convert and ImageMagick.
  • Kosmos OS [verified, /Users/paulbloch/kosmos-os-frame]: src/apps/maps/ uses Leaflet. MapCanvas.tsx loads tile.openstreetmap.org directly; server/services/mapsService.ts uses the public Nominatim and the OSRM demo server. Those data paths break the policies in section 6, so we keep the feature intent and not the endpoints. docs/apps/00-kosmos-os-primitives.md does not exist in this repo, so the desk tokens from browser h1 are used; re-check when it appears.

4. Architecture#

(a) Host-rasterised raster tiles. The Mac draws 256 px tiles at device scale and sends them. A raw RGB565 tile is 256 x 256 x 2 = 131 KB; a 1440 x 900 view needs 24 to 30 tiles, so 3 to 4 MB, about 85 s at 47 KB/s. Run-length coding helps flat colour, not antialiased text [estimate: 10 to 30 KB per tile]. Guest CPU is tiny and fidelity is best, but text is baked in and each restyle is a full tile set. Five styles means five data sets.

(b) Vector tiles drawn natively. The host sends geometry; the guest fills, strokes and labels it. A dense urban MVT tile is about 20 to 60 KB gzipped [estimate]; a compact form after zoom filtering and quantising should be 5 to 15 KB [estimate, M1 gate]. Guest CPU is the cost: protobuf decode, thousands of fills, labels. Restyling is free.

(c) Hybrid (recommended). The host reads a PMTiles file (section 6) and writes our compact tile form per tile: features filtered by zoom, clipped to the tile plus a 16 px buffer, polygons pre-triangulated (earcut, section 8), and labels pre-shaped as ASCII with anchors and priorities. The guest does what is view-dependent: transform, scan triangles, stroke, cull labels, and apply one of five palettes. Raster appears only for satellite (P2) and host-side previews.

Criterion (a) raster (b) vector (c) hybrid
Channel per view 3 to 4 MB [estimate] 0.2 to 0.5 MB [estimate] 0.2 to 0.5 MB
Guest CPU very low high medium
Fidelity fixed, best crisp, restylable crisp, restylable
Five styles five data sets free free (palette)
Renderer work blits polygons, strokes, labels triangle scan, strokes, labels
Biggest risk channel guest speed host writer complexity

Recommendation: (c). If the guest misses 200 ms per view at M3, fall back to a raster base layer with vector labels on top.

Cache: the guest keeps about 64 parsed tiles (a guess to measure); the host keeps compact tiles keyed by PMTiles hash, tile id and format version.

5. Routing and geocoding#

All run on the Mac, reached on 127.0.0.1 by the host bridge. Nothing goes to a public server.

Engine Licence Notes
Valhalla MIT [reported, official repo] Routing; car, bike, foot; isochrones [reported]. First choice
OSRM BSD-2 [memory] Fast car routing; keeps graph in memory [reported]. Fallback
GraphHopper Apache-2.0 core [reported] Hosted API is paid and keyed; not needed
Photon Apache-2.0 [verified, LICENSE] Geocoder with typeahead; needs an index built from OSM. First choice
Pelias MIT [memory] Heavier Elasticsearch stack. Skip for v1
Nominatim GPL-2.0 [memory] Self-hosted only, as a separate service; fallback search

Each region's routing graph and search index come from the same extract, built on the Mac. Build times and sizes are unmeasured; M0 measures them.

6. Data licences and tile policy#

  • OSM data is ODbL [reported]. Show "© OpenStreetMap contributors" on the map. Offline packs are for the owner's personal use; sharing a derived database triggers share-alike, so the about box says so.
  • Public raster tiles at tile.openstreetmap.org [verified, operations.osmfoundation.org/policies/tiles]: heavy use needs Operations Working Group permission; "Offline use is not permitted"; bulk prefetching is banned; access "may be blocked without prior notice"; apps must send a unique User-Agent. Not allowed.
  • Public Nominatim [verified, operations.osmfoundation.org/policies/nominatim]: an "absolute maximum of 1 request per second"; results "must be cached on your side"; heavy users should self-host. Not allowed for search.
  • Public OSRM demo [memory]: no service level. Not allowed.
  • Protomaps daily builds [reported, docs.protomaps.com/basemaps/downloads]: ODbL data, BSD-3 code, CC0 design; attribution required. A planet file is reported at about 120 GB, and sizes vary by date. pmtiles extract with a bounding box makes a regional file [reported]. Check each build's BLAKE3 hash.
  • OpenMapTiles [reported]: BSD schema with CC BY design; credit "© MapTiler © OpenStreetMap contributors". Its layer names serve as reference.

Result: the app reads only local files and local services. The footer attribution is the only visible legal item.

9. Security and privacy#

  • Location is sensitive. The guest has none. If "here" is wanted, the host reads CoreLocation only after the Mac's prompt and an in-app approval. A plain Python process may not get the prompt [memory]; test with a signed helper at M5.
  • Remote calls: none in v1. If a later version adds one, settings name the service and the exact fields it receives.
  • Searches, saved places and history stay on the host store (browser e4 style).
  • Outward actions (share, open in another app) need a UI prompt.
  • Logs record request paths and counts, never search coordinates, unless debug logging is on.

10. UI specification#

Tokens from browser h1: C_INK, C_ACC, C_CARD, C_BRD, C_PAGE, C_MUT; title bar 44, toolbar 44, footer 22; F_REG and F_SMALL faces.

Rules: plus and minus, arrows and Page Up and Down zoom and pan (P0); the wheel and drag too. Escape clears search, then closes directions. Search results are a list of up to eight; Enter takes the first. The attribution footer is never hidden. No °: coordinates are written with N, S, E, W.

11. Framework needs#

  • Text field, list and toggle widgets from widget kit v2 (not built).
  • A host map service on the browser frame format (browser-architecture.md b1, b2) with new message types: tile, search, route. The browser's list has none of them yet.
  • A host file service for offline packs and saved places (P1).
  • Renderer work in section 7.

Test plan: offline by default (tests read fixtures; a socket open fails the test). Golden screenshots from QEMU via scripts/snap.sh, compared with host renders of the same tile. Host-side protocol tests (round trip, CRC, truncation). Parser tests with a triangulation area check (within 0.5 percent). A mutation check: break one filter rule and confirm a golden fails. A policy test counts outbound hosts and fails on any host other than 127.0.0.1.

13. Risks#

  1. Guest speed under QEMU may miss M3. Fallback: raster base layer.
  2. The real channel may be slower than 47 KB/s. Mitigation: 120 KB first-paint cap, zoom-based detail limits.
  3. Small ASCII labels. Mitigation: scale 2, fewer labels.
  4. Regional extracts can be large, about 1 to 2 GB for a big metro [estimate]. The owner picks the region.
  5. Licence drift (CoMaps, Protomaps builds). Mitigation: pin builds by hash; recheck before each port.
  6. No live traffic or transit in routing. Stated in the UI.

14. Effort#

P0 is about L: 10 to 14 weeks for one developer, including the renderer work in section 7. M0 to M2 (host and channel) can run in parallel with the renderer.

15. Verified versus memory#

Verified (opened or run): desk renderer and font code, Kosmos OS maps code and endpoints, the OSM tile and Nominatim policies, licence files for PMTiles, earcut, Photon, Organic Maps, CoMaps and Lucide, the Mac's tools.

Reported (search snippets): Protomaps licence split and planet size; OpenMapTiles licence; Valhalla MIT; OSRM and GraphHopper licences; MapLibre Native BSD-2; OsmAnd GPL; the CoMaps AGPL proposal; the 47 KB/s channel figure (repo notes).
