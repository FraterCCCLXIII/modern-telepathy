Porting method: Kosmos OS shell primitives to the Temple desktop

Edited 2026-10-27docs/apps/01-porting-method.md

Written 2026-10-27 from kosmos-os-frame at 636534e. The repo is "Kosmos OS" in the brief and "Arco OS" (package arco-os) in its README; this doc uses repo names. Marked (read) = checked in files this session. Marked (inferred) = estimate or reasoning, not run.

1. Classes and the decision rule#

  • N, native: UI written in HolyC on desk3 widgets, or as a tree for the interpreter (section 4).
  • H, host service: logic stays on the Mac in Node; the guest calls it over the channel (section 3). Reused unchanged when the module has no DOM or React.
  • S, spec only: read the behaviour, write new code. Used for web-specific code and for anything whose licence does not allow reuse (section 8).
  • X, skip: web, Electron, mobile or media-bound code, or not wanted on the desk.

Decision order: no DOM and no React gives H (run it, do not rewrite). Data the host owns gives N view plus H data. Pure UI gives N. Browser media (audio, video, map tiles, canvas-heavy) gives X, or H for the data only.

Effort uses the core-apps units: S about a day, M about three days, L about a week, XL more (inferred).

3. The host-service pattern#

3.1 Process. kosmos-hostd is a Node 22 process on the Mac, the runtime the Kosmos server already uses. It loads modules with no DOM or React: shared/math, shared/sheetFormula, shared/widgets, shared/manifest, shared/capabilities, server/stores, server/services, server/automations, server/mcp, server/skills (import graphs not traced, inferred). Not hostable: src/*, packages/app-sdk and platform-bridge (DOM), packages/editor-kit (React). packages/doc-interop touches DOM names in six files; check before loading. Server modules import server/env.ts (dataDirs) and server/bus.ts; hostd supplies both as small shims (read: calculatorService.ts).

3.2 Channel. Today, desk3 talks to scripts/browser-bridge.py over COM1 with a line protocol (03b-browser.HC: GET, W, ERR, OK). Each request is one round trip; core-apps measured the lockstep loader at about 1.4 KB/s. The plan's streaming gate is 50 KB/s with no per-chunk acknowledgement (inferred that this is unmeasured). Use the framing below, plus a sequence number and CRC. On Aiwnios, platform.HC declares only KsOpen, KsPresent, KsPresentRect, KsPoll, KsInject and KsExec (read). KsExec starts a process per call: fine for one-shot requests, wrong for events. Add loopback TCP natives (KsSockOpen, KsSockRead, KsSockWrite) to aiwnios-sdl32.patch (inferred: S to M).

3.3 Wire format. Records, not JSON. One record per line; fields separated by TAB; \t, \n and \\ escaped; first field is the op. Blobs over 4 KB go as BLOB n then n raw bytes. HolyC has no JSON parser; a TAB splitter is about 40 lines.

3.4 Typed bindings. One schema, two generated sides, one check. - hostproto/protocol.json: ops, field names and types, reply shapes. The only definition of a message. - tools/hostproto/gen.mjs: Node stdlib only, modelled on kosmos-engine/tools/protocol-sdk/gen.mjs (179 lines, --check fails when the committed output differs). It emits hostd/src/proto.ts (types, encode, decode, exhaustive dispatch) and desk3/hostproto.HC (op and field-index constants, encode and split helpers, no per-op logic). - hostproto/fixtures/*.rec: sample records that both sides must decode to equal fields. - Run --check in the pre-PR script.

Precedent in kosmos-os-frame: scripts/generate-prompts.ts writes build-time artifacts that the server reads (read).

3.5 Data stores. The host is the single source of truth. Each namespace is one SQLite file under the host data directory (read: server/stores/db.ts, data/db/<ns>.sqlite). Rules: 1. The guest never opens a database. It calls an intent (tasks.list, calendar.event.create), and hostd checks the app's grant first. This keeps one choke point, as the app-platform plan requires. 2. The guest keeps only the last reply, for drawing. On disconnect it shows a stale view with a banner. It does not write locally. 3. Anything that sends, deletes or spends needs a prompt answered in the UI before hostd runs it. 4. One hostd process owns each file (better-sqlite3 is synchronous). 5. The desk has one owner. Set the owner in hostd config and drop multi-user checks on the desk path.

4. UI translation#

4.1 Tree format. The guest does not parse JSON. A tree is indented records: indentation is depth, key=value are attributes, quoted strings are text.

Ids are host strings (up to 24 characters). The guest maps each id to a node index and sends the id back in events. Colours are palette slot names, never hex.

4.2 Interpreter. desk3/ui/tree.HC: a fixed pool of 512 nodes. TREE parses into the pool in one pass and lays out. Every frame paints with the existing Txt, RRFill, Button, Toggle, Check, Radio and Slider, and each interactive node gets a Hit with aux set to its index. Events leave as EV <id> <kind> [value]. SET changes one node's text and relayouts only if its width changes.

4.3 Layout subset. Measure, then arrange. Supported: row and col, gap, pad, fixed size, w=fill (equal share of remaining main-axis space), cross-axis start, center and end. Not supported: wrap, absolute positioning, percentages, min and max, grow weights, baselines, grids. Cost (inferred): one measure and one arrange per TREE, O(nodes), with text widths cached per (font, string). At 500 nodes this should be well under a millisecond, against the 3.9 ms full-redraw figure in the aiwnios README. Kosmos generated apps reflow through ResizeObserver; the desk re-lays out on window resize only.

4.4 Text and fonts. Four faces exist: F_REG, F_BOLD, F_SMALL, F_BIG, in one atlas (read: 01-core.HC). TW gives widths and Wrap gives paragraphs. Kosmos presets include Inter, IBM Plex, Source Serif and Space Grotesk; the desk has none. The font service is a foundation item.

4.5 Tokens. Kosmos OS has five preset families in src/os/themeTokens.ts: accent, radius, font, text scale, spacing (read). The desk has five styles (ks_sn: Longformer light and dark, macOS, Windows 11, Kosmica glass), each with 16 palette slots (ks_pal, names in ks_pn). Mapping: accent to ks_accov; radius to ks_rad and ks_radadj; text scale to a choice of F_SMALL, F_REG or F_BIG; spacing to default pad and gap; font ignored (one atlas). If the brief's "five token sets" meant something else, only this table changes.

4.6 Worked example: Timer.

Source (apps/timer/app.js, read). State is entries of {id, kind, label, endsAt, durationMs, remainingMs, status}. Presets run 1m to 1h. Functions: startTimer, pauseEntry, resumeEntry, removeEntry, tickDue, setAlarm. Persistence is localStorage key core.timer.v1, which is per viewer. Alerts call os.shell.notify and a Web Audio tone.

Split: - H: apps/timer/logic.mjs, extracted from app.js (inferred about 120 lines). The pure functions move out, with now and nextId injected for tests. hostd keeps entries in namespace core.timer, and a one-second interval calls tickDue. localStorage state moves to the host store. - N: apps/timer/ui.tree (v0: presets and list; custom durations and alarms wait for the text field) plus a small HolyC event handler. - Dropped: the tone. Options are the PC speaker that core-apps describes (unverified in desk3) or host playback.

Message flow: 1. guest to host: HELLO app=core.timer v=1 2. host to guest: TREE followed by the tree lines. 3. user clicks Pause: guest sends EV pause.k3 click. 4. host runs pauseEntry, saves, sends TREE (status changed). 5. each second, host sends SET r.k3 4:57, with no relayout. 6. at zero, tickDue marks the entry ringing; host sends NOTIFY core.timer "Focus block finished"; the guest queues a desk notification. 7. Remove: EV remove.k3 click; host removes it and sends TREE.

Effort (inferred): logic extraction S, notify S, timer UI S. The interpreter and the bridge messages (HELLO, TREE, EV, SET, NOTIFY) are M each and shared by later apps. About a week once they exist.

Tests: Node unit tests of logic with a fake clock; a TREE fixture; a golden at 1440x900 with the same entries as the web timer.

Source: shared/manifest.ts (read). The desk registry reads apps/<id>/manifest.txt at boot (key=value lines, same escaping as the wire) and builds the Applications folder. This replaces the fixed 11-entry arrays in desk3/02-ui.HC (read).

6. Porting checklist and tests#

Checklist, per primitive: 1. Classify with section 1 and fill its table row. 2. List imports: grep the directory for from ['"]react, document., better-sqlite3, node:. 3. Write the behaviour spec: states, events, data, store owner. Check the licence (section 8). 4. H: add ops to protocol.json, regenerate, then --check. 5. N: draw with desk3 widgets, or add tree node types. List the events. 6. Add a scene to aiwnios/golden.HC and capture at 1440x900 with golden.py. Any pixel change needs a stated cause, as in the aiwnios README. 7. Keyboard: tab order, Enter, Esc, focus returns. 8. Frame cost: check the Monitor's per-phase timers against the full-redraw budget. 9. Add a port note under apps/templeos-holyc/docs/apps/.

Tests: - Protocol: fixture records decode to equal fields on TypeScript and HolyC; Node tests for the TS side; a kernel-test-style harness on Aiwnios for HolyC. - Logic: Node tests with an injected clock (timer, calculator, tasks). - Golden: golden.HC scenes compared with golden.py and pxdiff.py. - Parity harness: one seeded SQLite fixture; the web shell (Playwright against the dev server) and the desk (drive.HC on Aiwnios) show the same data. Compare structure, not pixels: labels as text, rectangles within 2 logical px, and a hash of the store after a fixed event script. Pixel parity cannot hold across two renderers; the aiwnios gate only holds desk against desk.

8. Risks, licences, verification#

Licence. kosmos-os-frame has no LICENSE or NOTICE file, at the root or to depth 4 (read: find). No package.json, root or workspace, has a license field (read: grep). Treat all code as all rights reserved. The default for every primitive is S: rewrite from behaviour. H, which runs their modules unchanged on our Mac, needs the owner's written permission even though it is use, not redistribution. Dependencies in node_modules are MIT: @openuidev/react-lang, @openuidev/react-ui, better-sqlite3 and react (read: package.json and LICENSE). The Lucide and Inter licences come from core-apps-plan and were not re-checked.

Risks. - The stores assume multiple users and server auth. The desk has one. Strip the checks; do not fork the code. - The streaming rate is a target, not a measurement. - Layout cost on large pages and long text is unmeasured. - Scope: about 60 rows, of which roughly 40 are X or deferred. Studio, Social and Documents must wait for the framework. - Pixel parity across renderers is impossible; see section 6.

Verified by reading: line and dependency counts; desk3 widget, app and style signatures; aiwnios README and platform.HC natives; timer source; app-sdk and manifest types; db.ts; themeTokens families; widget registry names; catalog groups; protocol-sdk generator header; licence fields; absence of LICENSE and socket natives.

Inferred: all effort figures; layout cost; channel rates; the hostd import graph; the timer extraction size; doc-interop Node compatibility; the contacts store location (not found).
