Serial setup that works (for the browser painter agent)#

KS_TVM=/tmp/tvm-host KS_SERIAL_PORT=4569; snap.sh; send files; THEN start hostd.py (QEMU serves one client; a hub left connected makes serial-send hang). Guest TX reaches the host fine. The trap is RX: the UART gives one byte, and the next only after the guest reads it, so a read loop that stops at the first empty look gets about one byte per frame (70 bytes took 1 s). HlRead spins up to 0.5 ms for the next byte (3 ms after an ack), 4 ms cap per frame. Chunk 256, ack per chunk and at frame end. Pointer in tests: 1.5 px per unit at 1x; apps-host/hub/tests/vmmouse.py corrects by finding the arrow in a screenshot.

Known bugs and untested#

  • One reader at a time: PrPoll returns while a hub call is pending (hl_state==1); hub frames of other types are acknowledged and dropped. v1 browser traffic is not served by the hub and was not run with the hub.
  • Keyboard shortcuts none; favourites not saved.
  • A stale hover highlight can remain in another window layer (core behaviour).
  • ~/Music default scan unmeasured (cap 2000 tracks, depth 4).
