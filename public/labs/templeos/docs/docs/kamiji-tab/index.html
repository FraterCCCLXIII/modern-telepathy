Settings > Kamiji: characters, creator, host service

Edited 2026-10-27docs/kamiji-tab.md

Phase A (host side) done 2026-10-27; phase B (HolyC) is the plan at the end. Follows kamiji-on-templeos.md (route R2, host-baked sprites; it is the permanent fallback there). Differences from that study: it did not find the creator (below); sprites are RGB565 with keyed transparency, not 16-colour KSCHAR.BIN; they are rendered with the browser engine and three.js from the kamiji repo, not Blender; they cross the hub in base64 chunks instead of a file push (thumbnails are small). Licence: characters are CC BY-NC 4.0 with unresolved provenance rows, so this stays local use.

What the Kamiji are (all under /Users/paulbloch/Documents/github/kamiji)#

31 characters, GLB only: the Kamiji hand assets/kamiji.glb, 14 Kamikin assets/mochi/*.glb (index.json: id, name, species, persona, clips; six face PNGs each in *.faces/), 16 Rubbernose assets/rubbernose/*.glb. No standing portrait, turntable or thumbnail image exists for any of them (checked kamiji, kamae art-source, kosmos-engine/assets/kamikin = baked source folders, not images). kamiji-demo, kamiji-game, kamiji-rig, kechimyaku-lineage-nexus hold no creator and no character files of this family. No LFS: the GLBs are real files on disk; nothing was pulled.

The creator tool#

The Studio, kamiji/site/studio/ (README there): a no-build static page, prototype status. Parts, 35 morph sliders, colours, accessories, expressions, poses, roster, JSON and GLB export, all 31 bases. It needs three.js 0.186.1, which its import map takes from jsdelivr; kamiji/node_modules/three (same version) is on disk, so no download is needed. It has no URL parameter for a character and no host save: it keeps the current character in localStorage key kamiji.studio.current.v1 and its roster in ...roster.v1, and exports by download.

The hub makes it work without editing the kamiji repo: svc_kamiji.py runs a read-only loopback server (thread, 127.0.0.1, free port; serves only site/, assets/, node_modules/three/), rewrites the import map to the local copy, injects a script that seeds the chosen character and posts every change to /__kamiji/save (per-start token, Host check, 256 KB cap), which writes <work>/chars/<id>.json. Verified in headless Chrome: Pip opens in the Studio with its 3D view, offline (shots/kamiji-creator-1.png; first paint is slow under software WebGL). Saving does not re-bake the sprite in v1 (a card keeps its template sprite until kamiji_bake.py runs again; the creator JSON is kept).

Launch: the guest shows the URL in its own Browser app (edit reply, mode browser). Fallback edit ID window: the hub runs open URL after a second approval. No child process is started for the server; Chrome is started only by bake, through browser/host/engine.py (throwaway profile, pipe, no debugging port, stopped by its own pid). Gate if three.js is missing: cd /Users/paulbloch/Documents/github/kamiji && npm ci (about 228 MB, downloads from npm; never run by the service, it answers ERR with that text).

Files#

apps-host/hub/svc_kamiji.py (service, one edit in hostd.py build_hub: import svc_kamiji and hub.reg.add(svc_kamiji.Kamiji(cfg))), kamiji_bake.py, tests/test_kamiji.py (20 tests, python3 -I apps-host/hub/tests/test_kamiji.py). Config (all optional): kamiji_repo, kamiji_work (default ~/.cache/kosmos-hostd/kamiji: sprites/, chars/, user.json; git-ignored by location). Bake: python3 -I apps-host/hub/kamiji_bake.py [--sheet shots/kamiji-grid-1.png] (about 3 s for 31).

Protocol (hub wire: REQ id kamiji token op args; records TAB text, ASCII)#

op args reply
list [offset [count<=24]] KH total offset n creator_ready baked, then K id name species family pose kind baked edited persona (kind builtin or user)
info id KI id name species family persona pose kind baked edited
thumb id S\|M\|L [offset] [fmt] SPR id size fmt w h total crc offset n base64 (6000 raw bytes per reply; ask offset += n until total)
path id size PATH id size abs_path bytes (Aiwnios reads the file, no chunks)
edit id [window] EDIT id mode url port, or APPROVE
new name [template] [window] NEW id name template then EDIT ...; the id is u-<slug>; APPROVE comes before anything is created
status, bake, studio_stop STAT repo creator n baked port saves bake_running done/total note; BAKE started 0/31 (APPROVE first); STOPPED
No delete in v1. Approval scopes (token goes in the retry): exec:kamiji-studio:<repo> (server start, kept for the session), exec:open:<url> (window, used once), exec:kamiji-bake:<repo> (used once). The sentence in the APPROVE record names exactly what starts. hello stops the server and clears grants. The server also stops after 30 minutes idle.

Sprite record KSPR v1, little endian, 16-byte header: "KSPR", u8 ver 1, u8 fmt, u16 w, u16 h, u16 flags 0, u32 crc32 of payload. fmt 2 (default, all sizes): u16 words, row-major; 0xF81F is followed by a u16 count of transparent pixels, any other word is an RGB565 pixel (alpha cut at 128). fmt 1 (on request): alpha plane (4 bits, even pixel in the low nibble) then w*h RGB565, 115 KB at L. Sizes S 64x80, M 128x160, L 192x240 (hero). Standing pose: the idle clip at t=0, front, 14 degree turn, transparent canvas. Guest decode: loop over words, ks_fb write per pixel or skip the run.

PHASE B plan (applied after the merge; shared files)#

  1. Page and tab. AppSettings (desk3/03-apps.HC, tab names ks_sp_name[5] at line 96, now Appearance, Display, Dock, About, Menu bar): add "Kamiji" as page 5 and raise the count; add KamijiPage(x,y,w,h) in a new desk3/03q-kamiji.HC (loaded before the apps) so 03-apps changes stay at three lines (name, count, dispatch).
  2. Header and cards. Title, a New button (plus icon) at the right. Grid of cards (S sprite, 64x80 at 1x, doubled at 2x): name label under the sprite, hover lift (2 px, shadow), selection ring in the accent, an Edit button (pencil icon) on the card's lower right. Scroll with the page; 24 per page of list.
  3. Icons. Add pencil and plus (and user-plus optional) to scripts/gen-icons.py, regenerate KSICONS.BIN, add ids to the icon enum; follow the Icon Style editor rules.
  4. Hub calls through HostCall("kamiji",op,args,owner,tok) (03h-hostlink.HC), results read in the owner's tick via HlDeliver. One reader rule: HostPoll reads the port only while a call is pending and the v1 browser reads whenever it is open: open the Browser tab first, then Kamiji calls and the Browser must not poll at once; keep one call in flight, thumbnail chunks queued from the page's Tick. The reply is capped at HL_MAXRX 12000: chunks of 6000 raw bytes fit.
  5. Lazy load. On page open: list; queue thumb id S 0 for visible cards; assemble chunks into a malloc'd buffer per card (CRC check, KSPR decode into a 64x80 U16 plus a key); cache in memory for the session; progress ring on a card until it is decoded. Placeholder: a grey silhouette.
  6. Edit and New. Edit sends edit id; New opens a one-field name prompt, then new name template (template = the selected card, else kamikin-kon). On APPROVE show the guest prompt with the hub's sentence and Allow/Cancel, retry with the token. On EDIT open the URL in the Browser app (new tab, docs/web-apps.md); if it fails offer "Open in a window" (edit id window, second approval).
  7. States. Empty (no sprites): "No sprites yet" and a Bake button (bake, approval, progress from status every 2 s). Error: creator_ready 0 or ERR text: "Creator not available: see docs/kamiji-tab.md" with the ERR note below. Hub down: the existing hub-offline state.
  8. Aiwnios parity. hostlink-aiw.HC runs the request through hostd.py --call --rec, so the page code is shared; for thumb use path and read the file with the platform file read instead of chunks. The decoder is integer only (RGB565), identical on both builds.
  9. Gates. kslint.py clean; x86 and Aiwnios first-frame shots of the Settings Kamiji page with 31 cards (shots/kamiji-settings-x86.png, ...-aiw.png); hash equal for the grid with fixture sprites; Edit opens the Studio in the Browser with the right character; New creates u-... and shows a card; approval prompts shown and refused cleanly; full grid loads in under 15 s on serial; no frame stalls while thumbnails stream.
