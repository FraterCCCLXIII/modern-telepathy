Wallpapers: photos on the desk (phase A host side done, phase B guest side planned)

Edited 2026-10-27docs/wallpapers.md

The guest has no image decoder and the serial link moves about 16 KB/s (docs/browser-architecture.md b), so the Mac prepares every picture. Files: apps-host/hub/ksw.py (format, converter, reference renderer), svc_wallpaper.py (hub service wallpaper), fetch_pexels.py + fixtures/wallpapers/pexels-manifest.json (free pack), tests/test_wallpaper.py, tests/bench_wallpaper.py. Registered by two lines in hostd.py build_hub (import svc_wallpaper, hub.reg.add(svc_wallpaper.Wallpaper(cfg))).

KSW v1 (little endian, 40 byte header, then w*h pixels)#

Pixels are RGB565 (pixfmt 0) or RGB555 (1), row major. Header fields: KSW1, version 1, header words 10, pixfmt, flags (bit0 refinement, bit1 dithered, bit2 menu bar text light, bit3 dock text light), w, h, screen_w, screen_h (logical size composed for), dominant r g b, average luma, menu band luma, dock band luma, dim %, blur, focal x and y (0..1000), source aspect x1000, fit mode (0 fill, 1 fit, 2 stretch, 3 centre, 4 blur-fill), scale (1 or 2), CRC-32 of the pixels, refine_w, refine_h (size of the refinement the host can send). Guest expands 565 to 888 by bit replication ((r<<3)|(r>>2)). The working size is the guest's own lowa size, SW/4 x SH/4 (360x225 at 1440x900 at 1x, 720x450 at 2x), so no resampling is needed: the picture is fitted, blurred, dimmed and box-reduced on the host, dithered (ordered 8x8) to 565, and Up4 in the guest enlarges it by four exactly as for the gradient wallpapers. A refinement is a second KSW with flag bit0 at twice the size (or a better dither); the guest swaps it in when complete.

Hub records (service wallpaper; REQ id wallpaper token op args, replies RES id OK then these; text is ASCII)#

op args reply
list WL n default fit dim blur, then W id kind(gen/pexels/user) name credit url mw mh lum domhex
pref PREF id fit dim blur (read at boot)
thumb id TH id 96 60 base64 (11520 bytes RGB565)
info id w h [fit= dim= blur= refine=1 fmt=555] KSWI id total w h flags lum lum_menu lum_dock domhex refine_w refine_h
get id w h off count [opts] KSWD id off n total base64, n at most 40000 (a reply stays under the hub's 64 KB frame)
export id w h [opts] KSWF path bytes (file in the work directory; Aiwnios reads it directly)
add_from_file path ADDED id name; first try returns APPROVE fs:read:<path>, the grant is used up by the call
pick ADDED id name or PICK cancel; opens the Mac's chooser (osascript, public.image), so no token
remove, set_default id [opts] REMOVED id, PREF ... (built-in pictures cannot be removed)
Errors are ERR text. Rendered files are cached (40 kept). State is in wallpaper_dir (config.json; default
~/.cache/kosmos-hostd/wallpapers: store/*.jpg masters, thumbs/, cache/, index.json, prefs.json, credits.txt) with its own
.gitignore of *, so nothing in it can be committed even when placed inside the repo.

Intake rules#

50 MB file cap; 100 Mpixel cap and Pillow's bomb check (DecompressionBombWarning is an error); content sniffed (JPEG, PNG, WebP, GIF, BMP, TIFF, AVIF, HEIC), the extension must be an image name; SVG, PDF, text refused; truncated files refused; HEIC through /usr/bin/sips (size read first); embedded ICC profile converted to sRGB; alpha flattened on black; orientation applied; every other tag (EXIF, GPS, XMP) dropped because only pixels are copied into a new image; the stored copy is a JPEG at most 3840 px long; ids match ^[a-z][a-z0-9_-]{1,31}$ and every stored path is checked inside the directory; at most 40 user pictures; add_from_file accepts only an absolute path without .. and not a link. The approval text names the file and says a copy is kept.

Numbers (measured here, 16 pictures: 4 generated and 12 Pexels; tests/bench_wallpaper.py)#

layer bytes as base64 at 16 KB/s host time
320x200 128,040 10.4 s 40 to 70 ms
360x225 (1x base) 162,040 13.2 s 40 to 70 ms
480x300 288,040 23.4 s 25 to 90 ms
720x450 (2x base or refinement) 648,040 52.7 s 60 to 120 ms
native 1440x900 (Aiwnios only) 2,592,040 211 s by serial, a file read on Aiwnios
thumbnail 96x60 11,520 0.94 s each
Base64 costs a third; the raw 360x225 layer would be 9.9 s. Quality (guest pipeline reproduced in numpy, against the original fitted to
1440x900): mean PSNR 32.1 dB for the sharp path, 31.0 dB with the glass blur (BoxLow); the 565 step alone costs about 38 dB
(invisible); smooth gradients 33 to 45 dB, busy photos 21 to 29 dB (detail is lost by design, the base is a quarter of the width).
Ordered dither removes the contour bands of smooth gradients (shots/wallpaper-banding.png, 6x contrast). Sheets:
shots/wallpaper-generated-1.png (generated), local shots/wallpaper-sheet-N.png (photos, not committed). The 720 layer
only helps when the guest works at SW/4 = 720 (retina); at 1x it is resampled to 360 and gives no gain (32.5 against 32.1 dB).

Credits and licence#

Photos are from Pexels (Pexels License: free for personal and commercial use, no attribution required, appreciated; do not sell unaltered copies). The manifest lists photo id, page URL, image URL, photographer and profile, title, tags. fetch_pexels.py makes one request per image to images.pexels.com (https only, no redirects, User-Agent naming the tool, 2 s pause, 20 s timeout, 8 MB cap, image content type) and writes credits.txt. No account, no API key. An optional pexels_api_key in config.json is reserved for a later search feature (api.pexels.com, header only); it is not used yet. Images are never committed. The four generated pictures need no download.

Phase B plan (guest, after the merge; touches desk3 shared files)#

  1. 03-apps.HC AppSettings, page 0: replace the three-button "Wallpaper" row (ks_wvar) by a section: tabs Built in | Pexels | Files; a grid of 96x60 thumbnails (ks_wth[], drawn with the existing 565 expansion, selected one ringed with C_ACC); Choose from Files... (calls pick) and Add path... (text entry, calls add_from_file, shows the APPROVE prompt through the existing hub prompt); radios for the five fit modes; two sliders Dim (0..80) and Blur (0..100); Apply; a progress bar under the grid while a KSW loads. The old gradient variants stay as the first three entries of Built in (id ks_wvar kept).
  2. New file desk3/03w-wallpaper.HC (loaded after the hub client): WallList, WallThumb(i) (lazy, six visible at a time, 0.94 s each), WallFetch(id) (info, then get in 40000-byte steps, base64 decode into a U16 * buffer, CRC check with the existing crc32), WallApply.
  3. 01-core.HC BuildWall: when ks_wphoto is set, skip the gradient loops: expand the 565 base into lowa (Fill/Copy loop, about 80k pixels, a few ms), Up4(lowa..., wall) for the sharp wallpaper, BoxLow + Up4 into wallb for glass (one extra Up4, about 25 ms), then the dots and variant lines as now (variants 0 only for photos). At retina with a 360 base, upsample 2x with KsLerpRow pairs first. Free the buffer after the build (the guest keeps only wall and wallb).
  4. Damage: loading ends in Rebuild() (already WallDrop; BuildWall; DamageAll); the progressive refinement ends the same way. While loading nothing is damaged; the style's own wallpaper stays until the swap.
  5. Per-style default: ks_wpid[NS] (id or empty); SetStyle builds the style's photo if its id is set (hub pref returns the global default; per style ids are stored as set_default options style=N, to add in svc_wallpaper before phase B).
  6. Contrast: flags bit2 and bit3 pick light or dark text for the menu bar and the dock labels; lum_menu and lum_dock choose the scrim alpha (low luma: 0; mid: 40; light: 70) in Menubar and DockGlass; dom tints the accent only when the user asks (Match colours).
  7. Persistence: the guest keeps nothing. At boot (after sys hello) the guest calls wallpaper pref, then loads that picture in the background after the first frame. The host writes prefs.json on set_default. On Aiwnios the same call goes through hostd.py --call and the guest reads the exported .ksw file directly (any size, native 1440x900 or 2880x1800 in one read).
  8. Gates: (a) unit tests above pass; (b) round trip on x86 QEMU: 360x225 KSW arrives, CRC matches, screenshot equals the reference renderer within 2 levels; (c) UI thread never blocks more than 50 ms while loading (the hub's PENDING frames and chunked reads); (d) boot time unchanged for no photo (KS-READY, plan: 1.5 s after go); with a photo, the first frame is the gradient and the swap comes 13 s later; the boot image gains nothing (thumbnails fetched on demand) unless the four generated thumbnails (46 KB) are baked into KSICONS.BIN; (e) kslint clean for Aiwnios; (f) a hostile file through pick and add_from_file shows an error and leaves the desktop unchanged.
