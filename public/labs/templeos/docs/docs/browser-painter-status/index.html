Browser M2 painter: status (stream 3)

Edited 2026-10-27docs/browser-painter-status.md

Branch task/templeos-shell. Scope: guest protocol and DLIST painter in HolyC (desk3/browser/*.HC), fake host (scripts/browser-fake-host.py).

What works (verified in the QEMU VM)#

  • The desk compiles with desk3/browser/{cache,dlist,proto,paint}.HC and the 03b hooks; the Browser opens (driver, no keys).
  • Page 1 (real Chrome bands from browser/host/dlist.py, 2 bands) paints: heading, wrapped text, links with underline, box and placeholder image, control. Screenshot: shots/browser-m2-page1-desk.png (1440 wide).
  • Page 2 (60 links, 7 bands) paints; first paint 100 ms after NAV (busy loop on). Screenshot: shots/browser-m2-page2-desk.png, status crop shots/browser-m2-page2-status.png.
  • Page 3 and page 4 were loaded; screenshots exist (shots/browser-m2-page{3,4}-desk.png). Not inspected closely.
  • NAV, HELLO and BANDREQ frames reach the fake host; bands come back; CRC checks pass.
  • 20000-byte bench (new protocol, checksum checked on the guest): chunk 128 in 1167 ms (17.1 KB/s), chunk 512 in 1236 ms (16.2 KB/s); both "checksum ok". Screenshots: shots/browser-m2-bench-chunk128.png, shots/browser-m2-bench-chunk512-status.png.

Not verified#

  • Scroll step cost (no measurement taken).
  • Page 1 first paint with the busy loop (the 6.9 s figure predates it).
  • Hit testing and link click (the link ids are wired, not clicked).
  • NAK retransmit under real loss (the gap path is written, never triggered).
  • Aiwnios build (not attempted).
  • FIXED and STICKY prefixes are tracked, not applied; SCROLL offsets, gradients, shadows are placeholders.

Blocker found and fixed#

  • A call from an earlier file to a function defined in a later file (forward declaration) binds to a stub and does nothing in this build. Calls from 03b and cache.HC into proto/paint/dlist were silently skipped. Fix: 03b calls through function pointers set at load time by paint.HC (br_nav_fp, br_poll_fp, br_page_fp, br_link_fp, br_ready_fp, br_busy_fp); DlIndex is called from proto.HC after CaPut.
  • Earlier "no bytes" was not serial: the guest transmits fine (trivial OutU8 test and the v0 bench both reach the host).

Throughput#

  • The main loop sleeps between frames while the Browser is idle; the UART holds few bytes, so polls are rare. PrBusy keeps the loop unslept for 2 s after the last byte. Remaining limit: one PrPoll per frame (paced to the 60 fps cap). v0 busy polling measured 36 to 47 KB/s; the next step is polling inside the frame until the FIFO is empty or a few ms pass.

Reproduce#

The driver calls OpenApp(10) and BrowserGo(URL,TRUE) after 8 s (driver template: DrvGo in the desk file); the page bands come from dlist.encode_snapshot over a Chrome snapshot (see browser/host/dlist.py).

Next steps (ordered)#

  1. Poll inside the frame until the UART is empty or about 4 ms have passed while busy; re-measure the bench at 128 and 512.
  2. Measure first paint for pages 1 to 5 with the busy loop; measure scroll step cost (AppBrowser draw time).
  3. Test the link click path and NAK retransmission (drop a frame on purpose).
  4. Apply FIXED and STICKY offsets in PaintBand.
  5. Aiwnios build (aiwnios/build.py: the browser files are listed there already).
