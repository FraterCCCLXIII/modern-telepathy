Generative UI for agents

Agents that answer with apps.

Arco is the UI library of the kosmos.computer operating system. An agent does not paste a wall of text: it picks typed cards from a fixed vocabulary, and Arco draws them, themed and consistent.

Components

Cards an agent can generate

Nine block types have a schema in the kosmic-app-cards prototype. Each one below is drawn from its own spec by the same small renderer the demo uses, in Arco dark tokens. The type names are the real ones.

  • weatherCard prototype

    The only block with a React component in kosmic-app-cards: current conditions and a forecast, with 14 condition names. Source: src/blocks/WeatherCard.

  • taskCard, statCard, calendarCard, musicPlayerCard, codeBlock, terminalBlock, textBlock, formBlock prototype

    Each has a type and a Zod schema. taskCard and statCard also have a registry entry with a prompt description and an example, but their renderer there is a placeholder that returns nothing. The cards above are this page's own CSS drawings of those specs.

  • StatCards, CalendarSchedule, MediaCards prototype

    The Tier 2 block names in the Arco docs for the Kosmos shell, next to tool result panels. They run through OpenUI Lang today; the chat library has cards, charts, forms, tabs and follow-ups.

Sources: kosmic-app-cards src/types/blocks.ts, src/registry/*.ts; docs.kosmos.computer reference/component-tiers and guide/generative-blocks; Kosmos docs/rich-content-widgets-plan.md. The sources show no table block.

The feed

Cards stack in a feed, newest at the bottom. Each one is a small app: it has its own data, actions and state, so you can tick, edit or submit in place.

  • A micro app is a card. In the Arco docs, ephemeral blocks stay in the chat; durable ones become apps through app_create.
  • Card anatomy in the prototype notes: header with icon, title and badge; a body that is specific to the block; an optional footer of actions. prototype
  • A related prototype. The Hands (OpenHands Agent Canvas) feat/conversation-feed branch lists conversations as cards with a composer, reply, agent avatars, usage and diff stats, subagent and notification cards. That is a feed of conversations, not Arco code. prototype
  • Card actions, pinning and refresh exist as fields (actions, meta.pinnable, meta.refreshInterval) in the types. No renderer for them was found. planned

Generation

How agents generate UI

The agent never writes HTML or CSS. It emits data for blocks it was told about, the data is checked, and a renderer turns it into a card. Tokens do the rest, so every card looks like it belongs. This is the flow in the Arco docs.

  1. 1

    Prompt prototype

    The allowed vocabulary is generated for the target surface. In kosmic-app-cards, generateSystemPrompt() builds it from the registry. In the Kosmos prototype the prompts are still hand-maintained files.

  2. 2

    Emit available

    The agent streams OpenUI Lang in an openui-lang fence, or returns block JSON. Fences render while streaming in the Kosmos chat.

  3. 3

    Validate prototype

    Zod schemas check and repair output (safeValidateBlock). The Kosmos chat path has no render-time validation yet.

  4. 4

    Render prototype

    Each node resolves through a registry to a component: KosmicSurface in the cards library, AssistantBlock and AppSurface in Kosmos.

  5. 5

    Persist prototype

    Ephemeral blocks stay in the chat. A durable one becomes an app through app_create.

Render a surface prototype

From the header of kosmic-app-cards/src/index.ts. The agent's output is a surface: an id and a list of blocks.

import { KosmicSurface } from '@kosmos/app-cards';
import '@kosmos/app-cards/styles';

const schema = {
  id: 'weather-surface',
  blocks: [{
    id: 'weather-sf',
    type: 'weatherCard',
    location: 'San Francisco',
    current: { temp: 72, condition: 'sunny' },
  }],
};

<KosmicSurface schema={schema} />

One definition per block planned

The planned defineBlock() contract from the docs: one manifest drives validation, JSON Schema, the system prompt, the catalogue and rendering. Docs call it the highest-leverage Arco milestone.

defineBlock({
  type: "statCards",
  schema: z.object({ /* ... */ }),
  description: "Grid of KPI stat cards...",
  adaptivity: {
    inputProfiles: ["pointer", "touch"],
    minWidth: 220,
    idealColumns: { compact: 1, medium: 2, expanded: 4 },
    onCompact: "stack",
  },
  examples: [ /* golden samples */ ],
  render: (props) => <StatCards {...props} />,
});

Sources: docs.kosmos.computer guide/generative-blocks, reference/block-registry and reference/standards-map; kosmic-app-cards src/index.ts, src/registry/registry.ts; Kosmos docs/rich-content-widgets-plan.md (verified 5 Jul 2026 in that file). Arco says it defines the generative UI language, component vocabulary and tokens, and adopts MCP, ACP and JSON Schema.

Libraries and SDK

What is in the box

Arco is organised in four tiers. Names are from the Kosmos prototype repository and the docs.

  • Tier 0: Tokens prototype

    CSS custom properties --arco-*, switched with html[data-theme]. Installed apps get them as --os-*.

    src/styles/tokens.css

  • Tier 1: Primitives prototype

    Button, Input, Switch, Badge, Chip, EmptyState, plus Avatar and PasswordInput in the folder. BEM classes such as .arco-btn--primary. Agents never generate these directly.

    src/components/ui/

  • Patterns prototype

    MasterDetail, Section with FormRow and FormActions, SettingsLayout, ModuleDashboard, NavSidebar, ListItem, PreviewPane and more.

    src/components/patterns/

  • Tier 2: Blocks prototype

    Data-driven composites the AI assembles: StatCards, CalendarSchedule, MediaCards. Chat blocks in the repo: AgentTodoCard, AgentActionBlock, AgentThoughtBlock, AgentStatusLine, TurnMeter.

    src/components/agent-blocks/

  • Tier 3: Containers prototype

    AppShell slots, WindowFrame, MobileShell, AppSurface (generated reactive app host) and GeneratedSurface (inline chat host).

    src/os/, src/apps/appview/

  • Block registry planned

    The defineBlock contract above, with Zod validation, generated prompts and a Design System workspace as living catalogue.

    docs: reference/block-registry

  • @kosmos/app-cards prototype

    A separate package for cards in agent conversations: KosmicSurface, a registry, nine Zod schemas, --kosmic-* tokens, one finished block. MIT in its package.json. Its OpenHands extension scaffold is not built.

    kosmic-app-cards (one commit)

  • Kosmos SDK available

    @kosmos-computer/sdk and @kosmos-computer/types, MIT. Streams typed AgentEvents from a Kosmos environment, including os_ui events that the shell draws with Arco. Whether it is on npm was not checked.

    kosmos-sdk, docs: sdk/*

  • App Bridge SDK prototype

    For third-party apps running inside the shell, talking to it by postMessage.

    packages/app-sdk in Kosmos

  • OpenUI Lang available

    The renderer Arco uses today: @openuidev/lang-core, react-lang and react-ui, third-party packages the Kosmos prototype depends on.

    docs: guide/generative-blocks

Licences: the SDK is MIT; the Kosmos and docs repositories have no licence file in the archive. Kosmos and Arco are separate things: Kosmos is the OS, Arco is the library inside it.

Design tokens

One set of tokens, dark and light

Every shell and Arco surface reads --arco-* variables, never raw hex in new code. These swatches are the values from tokens.css (dark) and the archive's style catalogue (light). The accent is #7c9dff in dark.

Scales prototype

  • Type 11, 12.5, 14, 16, 20 px (--arco-text-xs to -xl)
  • Space 2, 4, 8, 12, 16, 24, 32 px (--arco-space-2xs to -2xl)
  • Radii 6, 10, 14 px, window 12 px
  • Motion cubic-bezier(0.32, 0.72, 0, 1), 140 ms and 240 ms
  • Window shadow 0 24px 64px rgba(0,0,0,.55), backdrop saturate(160%) blur(22px)
  • Fonts system UI stack and SF Mono

The Arco shell

Arco generates the content; the kosmos.computer shell holds it. Windows, a dock, a menu bar, a nav rail and a command palette are the containers cards live in.

  • Desktop: WindowFrame, Dock, HoverDock, MenuBar, NavRail, CommandPalette. prototype
  • Phone: MobileShell and MobileDock at 767 px and below. prototype
  • Default dock: chat, studio, apps, skills, files, maps, notes, email, tasks, contacts, terminal, settings.
  • The shell runs only with its backend, so no screenshot of it exists in the archive.

Get started

Get started

Run the Kosmos prototype prototype

You need Node.js 22 or newer. Arco lives inside the Kosmos monorepo. From its root, the docs give:

npm install
npm run setup   # first run
npm run dev     # shell :4610 + API :4600

Source: docs.kosmos.computer guide/getting-started. Repo: github.com/Kosmos-computer/Kosmos.

Talk to it with the SDK available

Mint an external client token in Settings, External Access, then:

npm install @kosmos-computer/sdk
import { KosmosClient } from "@kosmos-computer/sdk";

const kosmos = new KosmosClient({
  baseUrl: process.env.KOSMOS_URL!,
  token: process.env.KOSMOS_TOKEN!,
});
await kosmos.ping();
const result = await kosmos.chat.complete({
  message: "What can you help me with?",
  mode: "ask",
});

Source: docs: sdk/getting-started. Not run for this page.
