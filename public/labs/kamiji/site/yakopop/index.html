Learn a language from the words on screen.

Yakopop turns video, and game dialogue, into subtitles you can study. Every word shows how it is written, how it is read, what it means and how it works in the sentence, and lights up with the part of the translation it matches.

Try the live components All the components yakopop.com

Yakopop is its own project. The Kamikin characters on this site come from the Kamikin game, which lives in the Yakopop repository. Source code is private.

What Yakopop is for learning

Yakopop is a platform for learning a language from things you already want to watch. The repository describes it as word-synced, colour-coded bilingual subtitles for language learners. A learner watches, reads along, looks up what they do not know, practises, and comes back to review.

  1. Watch with layers available

    Each subtitle word is a column of up to five rows: the reading (hiragana for Japanese, syllables with stress for Spanish), the word in its own script, the romanisation (rōmaji, pinyin, IPA and so on), the meaning in context and the grammar (part of speech and form). Below the words sits a translation in the language you choose, split into chunks that are linked to words. Particles are drawn grey; every other word gets its own colour, and its chunk in the translation uses the same colour. Rows can be shown, hidden, resized and reordered, and profiles remember the choice.

    Source: packages/overlay/src/SubtitleStack.tsx, player/LayersPanel.tsx, player/prefs.ts

  2. Look a word up available

    Resting on a word opens a card with the word, its reading, its meaning in this sentence, the grammar, role markers explained (a topic marker is not translated, it is labelled) and a play button. For Japanese the card also pulls extra dictionary meanings, a JLPT level and a common-word flag from Jisho. While a card is open the video waits.

    Source: packages/overlay/src/WordCard.tsx, apps/server/src/dict/jisho.ts

  3. Practise available prototype

    Available in the web app: a practice quiz on a video, favourites, completion and progress, flashcard decks with spaced repetition, and a learning path per language made of video lessons, full-screen practice lessons with hearts and XP, daily quests and a weekly leaderboard. Speaking practice (record yourself saying the line, each word marked said, close or missed) is built into the player but only appears when the host supplies a speech-to-text service, so it is marked prototype.

    Source: README.md "Supported now", docs/plans/learning-path.md, packages/overlay/src/player/practice.ts

  4. Hear it available

    Click-to-hear voices: Kokoro for many languages, VOICEVOX characters for Japanese, and a designed-voice library. When no neural voice is reachable the player falls back to the browser's own voice. More in Voices.

    Source: packages/overlay/src/player/neuralVoice.ts, apps/server/src/routes/tts.ts

  5. Many languages available

    Videos in Japanese, Mandarin, Korean, Russian, Spanish, Hindi, Nepali, Thai and Tibetan. Translations into 12 languages (English, Spanish, French, German, Portuguese, Italian, Dutch, Polish, Turkish, Indonesian, Vietnamese, Hindi). The interface comes in 12 languages. Without a Claude key only Japanese can be built, with a free local annotator.

    Source: README.md "Languages", packages/shared/src/text.ts (OUTPUT_LANGS)

How transcripts and translations are made

The pipeline runs on the Yakopop server as queued jobs, not in the browser. Each stage is swappable: a provider registry lets a stage move to another service without touching the build. This is the real flow in apps/server/src/pipeline/build.ts.

  1. 1. Get the words available planned

    Available: the creator's or auto-generated YouTube captions, fetched with yt-dlp without downloading the video, or a .vtt, .srt or TTML file the creator uploads. The browser extension instead reads the text tracks the streaming page already loads (DASH and HLS manifests, WebVTT and TTML responses, or video.textTracks).

    Planned: speech-to-text for a video with no captions. The hook exists (transcribe stage, an OpenAI-compatible POST …/audio/transcriptions with response_format=verbose_json, reference server tools/stt/server.py running faster-whisper) but the pipeline does not use it yet, and video file upload is listed under "not yet".

    Source: apps/server/src/pipeline/captions.ts, providers.ts, docs/plans/extension.md, README.md

  2. 2. Cues available

    Whatever the source, the result is a list of timed text pieces. The builder groups caption text into chunks of about 200 characters with a per-character time map, so annotated sentences can be timed afterwards. Sound notes in SDH captions are dropped. The extension cuts a track into windows of about five minutes, each cached under a hash of language, target, annotator and text, so an episode is annotated once.

    // packages/shared/src/subtitles.ts
{ "start": 0.8, "end": 5.7, "text": "今日は天気がいいですね" }

    Source: packages/shared/src/subtitles.ts (Piece, parseSubtitles, splitWindows), pipeline/captions.ts

  3. 3. Annotate: words, readings, meanings, grammar available

    An annotator turns caption text into sentence-sized lines. Each line is a list of tokens [surface, reading, romanisation, gloss, grammar] and a translation made of chunks that point at token numbers. Three annotators exist:

    Claude (a language model with structured JSON output and per-language rules for the reading and romanisation systems; best quality; may be limited to admins on a server). A free local annotator for Japanese: kuromoji for splitting, readings and parts of speech, wanakana for kana and rōmaji, Jisho's public API for meanings, with rougher results and a label saying so. An external annotation service that speaks Yakopop's contract: POST {url} with { lang, target, pieces, options }, answering { lines: [{ start, end, t, en }] }.

    The rules the model follows are visible in the source: the tokens must add up to the caption text with nothing invented or dropped, a gloss is one to three words, particles with no equivalent get a role tag (#TOPIC, #SUBJ, #OBJ) instead of a translation, and every translated chunk carries the index of the source word it translates, or -1.

    Source: apps/server/src/pipeline/annotate.ts (systemPrompt, LANG_RULES), local-ja.ts, providers.ts

  4. 4. Translate available

    The annotator writes the translation into the creator's chosen target language as part of annotation, with every chunk linked to a word. Extra output languages travel on the same line as line.tr (a translation and one gloss per token, per language). Where an annotator does not translate on its own (the free local one), a sentence translator is used: a LibreTranslate-compatible service you configure, or MyMemory's free API (about 5,000 characters a day). A track in a dub's language starts from the captions in that language, or from the original captions machine-translated piece by piece, timings kept.

    Source: pipeline/providers.ts (translators), build.ts (translatePieces), packages/shared/src/text.ts (translationOf)

  5. 5. Time the words available planned

    Today: timing is per line, taken from the caption cues (timing: "line"). The words inside a line are spread across it by weight, the length of their romanisation plus a constant, on the client (wordAt, wordTime). That is what lights the words in the demos above. Planned: per-word forced alignment. The speech-to-text server can already return word times (timestamp_granularities[]=word), and the film voice tool uses them.

    Source: pipeline/build.ts ("word timing is interpolated on the client for now"), packages/shared/src/text.ts, tools/stt/server.py

  6. 6. Save and play available

    The track is saved as a new version of that language's lesson, the player fetches it as JSON, and the extension asks the server for windows. A creator can edit lines afterwards in the studio, with revisions and restore.

    GET  /api/lessons/:id
POST /api/overlay/windows        { lang, target, site, pieces }  → key
GET  /api/overlay/windows/:key   → status or lines
GET  /api/translation/providers  → which stages are configured
GET  /api/dict/:lang/:word       → dictionary entry for a word card

    Source: apps/server/src/routes/{lessons,overlay,system,studio}.ts. The window cache returns lines only for a key the client could compute, so it never hands subtitles to someone who does not hold them.

Voices and mouth shapes

Voices come from one text-to-speech server that speaks the OpenAI speech API, so a client does not care which engine says the line. The voice name picks the engine by its prefix. In the app, the browser never talks to that server directly: a thin proxy in the app server checks the request, limits it per user (or per address for guests) and passes it on.

  • Kokoro available

    Fast, soft voices in many languages, including Japanese. Voices can be blended to make new ones. Apache 2.0 model.

    Voice prefix kokoro:

  • VOICEVOX available

    Anime-style Japanese character voices. Each voice has its own terms of use and asks for a credit.

    Voice prefix voicevox:

  • Designed-voice library prototype

    Base voices designed from text descriptions with Qwen3-TTS and cloned into ten languages, with moods. It needs its own speech server (Apple silicon, or a PyTorch backend elsewhere), so it runs in development.

    Voice prefix qwen:, tools/voices

POST /v1/audio/speech
{ "input": "こんにちは", "voice": "kokoro:jf_alpha", "speed": 1.0, "reading": "こんにちは" }

200 audio/wav   24 kHz, mono
x-visemes: [[viseme, start, end], ...]   seconds into the audio; visemes aa ee ih oh ou fv mbp sil

The reading field gives Kokoro the kana when the Japanese pronunciation engine is not installed. The proxy accepts one short text per request (up to 400 characters), speed from 0.5 to 2, and answers 404 when no neural voice exists, so clients fall back to the browser's voice. Mouth shapes drive the characters' faces; the library's voices send speech start and end times instead.

Source: tools/tts/server.py, apps/server/src/routes/tts.ts, packages/overlay/src/player/neuralVoice.ts, docs/plans/anime-voices.md. Credits as the repository states them: VOICEVOX (春日部つむぎ, 白上虎太郎, ずんだもん), Kokoro, and Whisper via faster-whisper.

Games, characters and where Kamikin fits

Yakopop's decision record says it is the learning layer inside every game: games show dialogue through the overlay and words met in play are meant to go to the player's deck. Kamikin, the cute mochi universe for young children, is the first game built that way, and it teaches Japanese words.

  • Kamikin prototype

    Mochi friends on a round meadow wake things by saying their words, first in Japanese and then in the player's language. Two implementations exist in the repositories, a Godot slice and a port to the Kosmos engine. A public play site is not documented, so availability is unverified.

    Source: docs/kamikin-context.md, games/kamikin/README.md

  • Season 1 and the curriculum planned

    A design for lessons Monday to Friday (Hello Meadow, Pond Friends, Count the Stones, Snack Share, Review) with at most six new items each. Design and draft content, not a shipped course.

Provenance

Yakopop is the language learning platform; its repository is private (Modern-Telepathy/yakopop) and its README says it is live at yakopop.com. Kamikin is the game that lives in that repository. The Kamikin characters shown on the Kamikin page of this site are the game's mochi cast, converted for this site. This page is a Kamiji study of Yakopop's public description and of its code, read-only.

What is not claimed

Yakopop's README lists these as not yet built: video file uploads, speech-to-text for videos without captions, connecting a YouTube account, follows, playlists or series, reports from learners, analytics and billing (plans and limits work, but an admin sets plans until a payment provider is connected). The pricing page in the app is a mock-up, and this page states no prices.

Left out of this page on purpose: server addresses, deployment files, keys and settings, user accounts and data, and the way the voice server is reached in production. The TTS proxy is described only by what it accepts and returns.

Not checked against running builds: the status badges repeat what the repository's documents say. Nothing here was run against the live site except the extracted components on this page, which run on sample data.
